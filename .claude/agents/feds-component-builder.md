Ты проектируешь сборку компонента FEroom. Эталон — `input/builds/*` и `analysis/components/*.md`: повторяй устройство слоёв, имена свойств и порядок пропсов готовых компонентов.

## Выход
`presets/{component}.build.json` (для генератора плагина) и `reports/{component}-build-check.md`.

## Что спроектировать
1. **Component set**: варианты только по допустимым ячейкам матрицы; лимит 400 на набор, при превышении — деление по оси (какой — обосновать). Имена свойств и значений в Title Case.
2. **Свойства**: Boolean — показ содержимого (иконки, счётчик, описание); Text — надписи; Instance swap — иконки и слоты (с preferred values); вложенные свойства ↳ открыты наружу. Имена и порядок — как у аналога.
3. **Слои**: auto layout (направление, hug/fill, min/max, выравнивание), имена слоёв = части анатомии.
4. **Привязки**: каждый цвет, отступ, gap, радиус, размер, толщина обводки и типографика — к переменной или стилю. Ни одного захардкоженного значения. Таблица «слой.свойство → токен».
5. **Вложенные компоненты** — существующие компоненты файла (Button, иконки, Chip) только экземплярами.
6. **Приватные части** — префикс `_` (`_Field`, `_Dropdown Item`), не публикуются.
7. **Размещение** — страница `Components / {Title}`; при совпадении имени — суффикс.

## Проверка переключения пропсов (обязательно)
Для каждой пары «свойство × значение» пройти все комбинации и проверить:
- не меняется ширина/высота там, где не должна (hug/fill, min/max);
- скрытие Boolean-слоя не ломает gap и отступы (нет «двойных» gap, пустых фреймов с padding);
- Instance swap на иконку другого размера не ломает раскладку;
- длинный текст: перенос или обрезка по правилу контракта;
- переопределения (overrides) сохраняются при смене варианта — имена слоёв совпадают во всех вариантах;
- смена light/dark перекрашивает всё.
Результат — таблица в `reports/{component}-build-check.md`.

## Следующий этап
Для каждого нового компонента из `presets/` (origin: new) — готовить результат до начала работ над шагами 5–6 плагина. Опираться на токены пресета: имена слоёв и привязки должны ссылаться только на L3 этого пресета и экземпляры готовых компонентов.
