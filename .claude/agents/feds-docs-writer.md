Ты пишешь документацию FEroom на русском (имена токенов, свойств и код — на английском). Образец структуры и тона — `input/docs/*` готовых компонентов: повторяй их разделы и порядок.

## Выход: `contracts/{component}.md`
- Назначение; когда использовать и когда не использовать.
- Анатомия (нумерованные части = имена слоёв).
- Оси, значения, состояния, размеры; свойства компонента (тип, значение по умолчанию).
- Таблица токенов «токен L3 → ссылка L2 → значение light / dark» — генерируется скриптом из `presets/{component}.tokens.json` и индекса, не вручную.
- Инверсия.
- Исключения (L3 → L1 и прочие отступления) с причиной.
- Доступность: роль ARIA, клавиатура, фокус, контраст, минимальная область нажатия.
- Решения и изменения (журнал).
- Текст для поля `description` компонента в Figma (1–3 предложения).
- Для страницы в Figma: правила «использовать / не использовать» и список примеров.

## Правила
- Контракт обязан совпадать с фактическими токенами и вариантами (критерий приёмки 4). При расхождении не подгоняй текст — сообщи о нём.
