# Плагин FEDS — как установить и проверить

## Установка в Figma (desktop)

1. Figma → меню **Plugins → Development → Import plugin from manifest…**
2. Выбрать файл `Desktop/FEDS/plugin/manifest.json`.
3. Запуск: **Plugins → Development → FEDS**.

Сеть не нужна. Сборка лежит в `dist/`. После изменения пресетов, документации или кода пересоберите плагин:

```bash
cd plugin && npm run build
```

## Что умеет версия 0.3.7

| Шаг | Что делает |
|---|---|
| 1 · Анализ | Читает коллекции, режимы, переменные и стили. Находит битые алиасы, ссылки через уровень, сырые значения выше L1, переменные без scopes, дубли. Строит словарь L2 и пары `inverse-*`. Ничего не меняет |
| 2 · Компоненты | Каталог из 26 пресетов: **база** (L1 и общий L2), **13 готовых** компонентов, **12 новых**. У каждого показан статус в текущем файле: «в файле», «частично», «нет в файле», «отличается». Зависимости подтягиваются автоматически, если их нет в файле |
| 3 · Токены | Дифф: добавится / совпадает / отличается / лишний. Запись одной операцией (отменяется одним Ctrl+Z). Существующее меняется или удаляется только по галочке и отдельному подтверждению. Проверка контраста в light и dark |
| 4 · Документация | Документы компонентов в Markdown: все или выборочно, архивом `.zip` по папкам, одним `.md` или по одному. К ним добавляются таблицы токенов с реальными значениями из файла |
| 5 · Сборка | Мастер-компонент и спецификация по единому правилу (`docs/build-rules.md`). У каждого компонента два переключателя — «Компонент» и «Спецификация», оба включены по умолчанию; спецификация собирается сразу после компонента на его живых экземплярах. Сейчас: **Button** (повтор текущей сборки: 6 наборов, 1064 варианта; новый тип Inverse у Filled, Icon - Filled, Outline, Icon - Outline и Text — для тёмных и насыщенных поверхностей), **Skeleton** (новый: Line, Circle, Block — 30 вариантов) **Alert** (новый, по композиции Atlassian Flag: Subtle / Default / Bold, 48 вариантов; Bold сворачивается и не закрывается; действия — кнопки системы, на тёмной поверхности и на заливке — тип Inverse; Bold закрепляет светлую тему, поэтому одинаков в обеих темах) и **Select** — семейство: публикуется `Select` (Field: None / Vertical / Horizontal × Type × Size × Open × Inverse, 144 варианта), приватные части — контрол `_ Select / Button`, список `_ Select / Dropdown` (Default / Empty / Loading, тень на переменных) и пункты `_ Select / Dropdown Items` (S, M, L). Dropdown в каталоге не выбирается отдельно — подключается вместе с Select, Combobox, Multiselect. Перед записью каждое описание проходит проверку контраста WCAG AA (light, dark, Inverse) и совпадения цвета иконки с текстом. Текстовые стили не создаются: типографика новых компонентов привязана к переменным. Каждый компонент — на новой странице `Components / {Title}`, всё отменяется одним Ctrl+Z |
| 6 · Отчёт | Что создано, изменено, удалено и пропущено. Отчёт выгружается в `.md` |

## Сценарии проверки

**A. Исходный файл «Элементы · Основа стилей» (дополнение системы)**
1. Шаг 2: у базы и 13 готовых компонентов статус «✓ в файле», у 12 новых — «нет в файле».
2. Выберите, например, Tooltip → «Далее: дифф». Должны быть только строки «добавится» (L2, L3, стили) и ни одной «лишний» или «отличается».
3. «Записать в файл» → отчёт. Проверьте переменные `tooltip/*` в `3. Components` и `space|radius|size|typography/tooltip/*` в `2. General`.
4. «Проверить повторно»: дифф должен показать только «совпадает» (идемпотентность).
5. Ctrl+Z один раз: всё записанное исчезает.

**B. Пустой файл (сборка с нуля)**
1. Создайте пустой файл дизайна и запустите FEDS.
2. Шаг 2: выберите «База системы» и нужные компоненты (или «выбрать всё» во всех группах).
3. Дифф покажет «Будут созданы коллекции: 1. Primitives, 2. General (light, dark), 3. Components» и около 5 тысяч добавлений.
4. Запись займёт некоторое время, прогресс виден внизу. Для режимов light и dark нужен платный тариф: на Free в коллекции только один режим.

**C. Сборка Button и Alert (рекомендуется на копии файла «Элементы · Основа стилей»: там есть переменные, стили и иконки)**
1. Шаг 3: выберите Alert и запишите токены (добавится в том числе `alert/size/{s}/action-gap`).
2. Шаг 5 «Сборка»: отметьте Button, Skeleton и Alert (у всех включены «Компонент» и «Спецификация») → «Собрать». Button и Skeleton собираются первыми: Alert использует их экземпляры.
3. Появятся страницы `Components / Button` и `Components / Alert`: тёмная мастер-область с наборами и справа секция «Спецификация».
4. Проверьте: переключение свойств (Size, Type, State, Loading, Focused, Left/Right Icon, Label; у Alert — Role, Inverse, Title, Actions, Second Action, Close и открытые наружу Action / Second Action с их Loading); смену режима light/dark у фрейма; привязки в панели справа (у каждого значения стоит переменная).
5. Ctrl+Z один раз убирает всё созданное.

**D. Только спецификация в файле «Компоненты · Базовые»**: шаг 5 → Button → выключите «Компонент», оставьте «Спецификацию» → «Собрать». Спецификация соберётся на существующих наборах Button, её можно сравнить с исходной.

**E. Документация**: шаг 4 → «Выбрать все» → «Скачать .zip». В архиве `README.md` с оглавлением и папки «Готовые компоненты» и «Новые компоненты» с документами и таблицами токенов.

## Разработка

```bash
npm test
```

```bash
npm run typecheck
```

`npm test` запускает тесты ядра на реальном `input/tokens/variables.json` и всех пресетах.

- Ядро (`src/core`) не зависит от `figma`: анализ, дифф, план, контраст, каталог.
- Запись в Figma — `src/figma/apply.ts`, снимок файла — `src/figma/scan.ts`.
- UI — `src/ui` (UI3: цвета темы Figma, светлая и тёмная тема, русский язык).
- Каталог пресетов (`presets/*.tokens.json`) и документов (`scripts/bundle-docs.mjs`) встраивается при сборке.
