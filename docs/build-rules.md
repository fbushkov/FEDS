# Единое правило сборки компонента и спецификации FEroom

Правило выведено из устройства готовых компонентов в файле «Компоненты · Базовые» (Button, Badge, Checkbox, Chip, Status, Switch, Select; разбор — `analysis/components-structure.md`). По нему собираются и существующие компоненты (повтор текущей сборки), и новые. Машинная форма правила — описание сборки `presets/{component}.build.json` (формат ниже). Плагин FEDS исполняет его: шаг «5 · Сборка».

## 1. Наборы и варианты

1. Компонент — один или несколько **component set**. Если осей много, набор делится по оси формы, и эта форма уходит в имя набора: `Button / Filled`, `Button / Outline`, `Button / Icon Only`; `Checkbox / Left / M`. Лимит — 400 вариантов на набор.
2. **Порядок свойств:** контентные (Text, Boolean, Instance swap с префиксом `↳ `), затем `Focused` (Boolean), затем оси-варианты: `Size` → `Type` / `Role` / `Color` → `State` → `Loading` / `Inverse`.
3. **Имена** свойств и значений в Title Case. Булевы оси-варианты принимают значения `False` / `True`. Состояния: `Default`, `Hover`, `Pressed`, `Disabled` (+ `Loading` как ось).
4. Варианты создаются **только для допустимых сочетаний** (например, `Disabled` + `Loading=True` не существует).
5. **Сетка на холсте:** колонки — значения оси типа, строки — блоки по `Size`, внутри блока — `Loading` × `State`. Отступ сетки 80, между вариантами 20–40.
6. **Оформление набора:** заливка `color/bg/section/main`, пунктирная обводка `color/static/border/brand/firm` (1, dash 10/5), радиус 5. Мастер-область — тёмная подложка `color/bg/page/inverse-main`, каждый набор в своей секции с заголовком.
7a. **Варианты для особых подложек — на своей полосе** (`grid.backdrops`): если приватная часть компонента живёт на особой подложке (например, пункт списка на своей панели), в наборе она стоит на этой подложке, а не на нейтральном фоне. Фон набора — градиент с жёсткими границами полос, каждая привязана к своей переменной.
7b. **Семейство вместо набора оберток**: поле формы публикуется одним набором семейства (`Select`, далее `Input`) с режимом `Field` = None / Vertical / Horizontal; контрол, список и пункты — приватные части (`_`). Направление раскладки может зависеть от варианта (`layout.dir: {by: Field}`). Архитектура — `docs/forms-architecture.md`.
7c. **Тень — на переменных** (`shadow`: x, y, blur, spread, color), как у списка Select в файле; привязка к L1 допускается только явным исключением в описании сборки (`exceptions`).
7. **Инверсные варианты — на тёмной правой части набора** (как Checkbox, Switch, Button / Icon Only): заливка набора — линейный градиент с жёсткой границей, слева `color/bg/section/main`, справа `color/bg/section/inverse-main`. Уходит либо целая ось (`Inverse=True` у Alert), либо значения оси типа (`Inverse-primary`, `Inverse-secondary` у Icon Only). В схеме: `grid.split`.

## 2. Слои варианта

1. **Корень** — auto layout. Все отступы, gap, высота, радиусы и толщина обводки привязаны к `{c}/size/{s}/…`. Заливка и обводка привязаны к `{c}/{вариант}/{bg|border}/{state}` (у неинтерактивных: `{c}/{bg|border}/{role}`). Обводка внутренняя (INSIDE). Ни одного захардкоженного визуального значения.
2. **Focus Ring** — первый слой: прямоугольник вне потока (absolute), растянут по родителю (constraints STRETCH) со смещением наружу, скрыт, `visible → Focused`. Радиус `{c}/size/{s}/radius-focus`, толщина `{c}/size/{s}/border-focus`, цвет `{c}/focus-ring`. Смещение: 4 для XL/L, 3 для M/S; у текстовых кнопок — 3. В `Disabled` кольца нет.
3. **Иконки** — экземпляры иконок библиотеки (24×24, внутри вектор `Union`). Размер `{c}/size/{s}/icon`, цвет — заливка `Union` → `{c}/…/icon/{state}` или `{c}/icon/{role}`. Видимость — Boolean (`Left Icon`), подмена — Instance swap (`↳ Icon L`), по умолчанию `circle`.
4. **Текст** — у существующих компонентов текстовый стиль `typography/{action/}{c}/{s}/…` (как в файле). У новых компонентов текстовые стили не создаются: размер, интерлиньяж, трекинг и насыщенность привязываются к переменным `typography/{c}/{s}/{part}/{size|line-height|letter-spacing|weight}` напрямую, начертание Roboto — по части (`fontStyle`). Заливка `{c}/…/text/{state}`, содержимое — свойство Text. В контролах одна строка с обрезкой многоточием. В сообщениях текст переносится.
5. **Loading** (ось) — только у контролов, которые сами ждут результата своего действия (Button). Содержимое остаётся в потоке с прозрачностью 0 (размер кнопки не меняется). Поверх по центру лежит `Loading` (иконка `loader`, absolute, CENTER). В `Hover` и `Pressed` вместо неё показывается `Cancel`: иконка `x` и надпись «Отменить».
6. **Вложенные компоненты** — только экземпляры существующих наборов (Button внутри Chip, Select, Alert). Их свойства настраиваются через `setProperties`, а сами экземпляры открываются наружу (`isExposedInstance`): их свойства видны в панели родителя. В схеме: `expose: true`.
7. **Загрузка данных — Skeleton, а не состояние компонента.** Пока данные блока грузятся, на месте содержимого стоят экземпляры `Skeleton / Line`, `Skeleton / Circle`, `Skeleton / Block`, повторяющие раскладку (строки текста, аватар, контрол, изображение). Компонент, чьё содержимое ещё не пришло, не показывается. Компоненты, которые появляются только с результатом загрузки (Alert, Banner, Toast), Skeleton не содержат — ни в наборе, ни в спецификации: Skeleton заменяет содержимое блока, а не сам компонент. Большой спиннер — только для целой страницы без известной структуры. Правило касается всех текущих и будущих компонентов: у них нет своей оси Loading, если это не контрол из п. 5.
8. **Неинтерактивные контейнеры** (Alert, Banner, Hint, Status) не имеют Hover, Pressed, Focus и своей загрузки: по мировой практике (Material 3, Carbon, Atlassian, Polaris, GOV.UK) состояния принадлежат кнопкам внутри. Наружу открываются только действия (`Action`, `Second Action`), чтобы в экземпляре можно было включить их `Loading`. Кнопка закрытия статична и не открывается. Иконка роли и текст статичны всегда.
9. **Кнопки внутри других компонентов — кнопки системы, на тёмном — тип Inverse** (решение автора 21.09.2026). У Button свои типы и четыре состояния (Default, Hover, Pressed, Disabled). Для тёмных и насыщенных поверхностей у Button есть общий тип **Inverse**: Filled — светлая заливка и тёмный текст (главное действие), Outline — светлые рамка и текст (альтернативное), Text — только светлый текст (ссылки, «Назад», закрытие); у Icon Only — Inverse-primary и Inverse-secondary. Компонент с кнопками (Alert, Banner, Popover…) **не заводит своих кнопок и токенов кнопок**: на обычной поверхности — обычные типы, на тёмной и насыщенной — Inverse, выбор проверяется по WCAG на подложке хозяина. Если светлое на подложке не читается (жёлтая заливка), берутся обычные тёмные типы. Подложка одна в обеих темах (Alert Bold) — компонент закрепляет светлую тему на узле (`theme: light`, explicit mode `2. General`), и вложенные кнопки всегда берут её значения; в коде — `data-theme="light"`. Ради одного компонента новые типы кнопки не добавляются.
10. **Слои вне потока** (Focus Ring, Loading, Cancel) сначала выводятся из auto layout, и только потом по размеру родителя вычисляются их позиция и размер.
11. **Приватные части** получают префикс `_` и не публикуются.

10a. **Поля ввода и выбора — внутри Field** (как Input в `Field / Vertical`): Label (`↳ Label`, `+ Required (*)`, `+ Add. Text`), контрол открыт наружу, Description с подсказкой (`↳ Hint`) или сообщением проверки (`↳ Message` с иконкой роли), `+ Extra Space`. Type (Base/Error/Warning/Success), Size и Inverse — одно свойство для Field и контрола. Пример — `Field / Select`.

## 2b. Модель проектирования новых компонентов

1. **Токены** — основа: текущая трёхуровневая система FEroom. Её можно дополнять (новые L2/L3) и локально улучшать (значения, прежде всего колонка dark), не ломая зависимостей L3 → L2 → L1; каждое изменение существующего помечается `change` и проходит через подтверждение.
2. **Композиция** — по образцу Atlassian Design System (atlassian.design): части компонента, виды, поведение, группы. Берутся признаки, а не названия (Flag → Alert, Spotlight → Hint, Lozenge → Status). Матрица соответствий — `reports/atlassian-matrix.md`.
3. **Документация** компонента дополняется тем, что у образца устроено удобнее (разделы помечаются датой), а решения, расходящиеся с прежним текстом, выносятся в «Решения для согласования».
4. **Правила сборки** этого документа и проверки (`a11y`, `build`, `catalog`) подтверждают результат. Готовые компоненты дорабатываются позже или точечно.

## 2a. Доступность: контраст и цвет иконок

1. **Контраст WCAG 2.1 AA** на фоне варианта: текст ≥ 4.5:1, иконки и значимые графические элементы ≥ 3:1. Проверяются оба режима темы (light, dark) и все состояния, кроме Disabled (WCAG 1.4.3). Read Only — не Disabled: его текст должен читаться.
2. **Тёмная поверхность (Inverse) — только светлые токены `inverse-*`** во всех состояниях (Default, Hover, Pressed, Read Only, Error…): тёмно-синие и тёмно-серые оттенки на тёмной подложке недопустимы. Для текста и иконок на inverse берутся пары `*/inverse-hard` или `*/inverse-medium`; `*/inverse-firm` у ролевых цветов (danger, warning, success) в dark-режиме не проходит 4.5:1.
2a. **Тёмная тема — отдельная настройка, а не копия light.** Полупрозрачные и calm-цвета в dark берут светлые сплошные ступени; насыщенные заливки в dark темнеют, чтобы белый текст проходил 4.5:1; текст поверх заливки — `on-bold` (белый в обеих темах), а не `inverse-*` (он в dark меняется на чёрный). Исправление — `tools/dark_theme_fix.py`, аудит — `tools/audit_contrast.py`.
3. **Иконка в цвет текста.** Иконка и текст одной смысловой группы (кнопка, пункт, сообщение) используют один цвет в каждом состоянии: токены одного семейства L2 (`text/…/X` ↔ `indicator/…/X`) и меняются синхронно при Hover, Pressed, Disabled. Исключение — иконка с фиксированным системным смыслом (маркер успеха или ошибки рядом с нейтральным текстом).
4. **Проверка автоматическая**: `plugin/src/core/a11y.ts` + тест `tests/a11y.test.ts` проверяют каждое описание сборки до записи в Figma. Новые компоненты и расширения (в том числе инверсные варианты существующих) должны проходить без исключений; нарушения в исходной палитре существующих компонентов собираются в `reports/a11y-contrast.md` и исправляются только по решению автора.
4a. **Обе темы исправлены до порогов AA**: `tools/dark_theme_fix.py` (колонка dark) и `tools/light_theme_fix.py` (колонка light) подбирают ступени расчётом; `tools/audit_contrast.py` → `reports/contrast-audit.md` (реальных нарушений 0; ложные срабатывания эвристики перечислены с причинами). Проверка по слоям строгая для всех компонентов в обеих темах. Недоступные варианты (Disabled, Read Only пункта списка) исключаются явно: `a11y.exempt` в описании набора.
5. **Исправление существующего токена** — только с решением автора: в пресете у токена поле `change: {was, approved}`; валидатор и дифф показывают его как «отличается», запись — с подтверждением.

## 3. Спецификация

Спецификация — живые экземпляры собранного компонента на странице рядом с мастером. Собирается вместе с компонентом (по умолчанию включена); отдельно — только если компонент уже есть в файле.

1. **Каркас:** секция «Спецификация» → белая подложка `color/bg/section/main`, радиус 24, отступ 80, gap 40. Заголовок — стиль `typography/page/title`, описание — `typography/content/body/default`.
2. **Разделы (колонки):** заливка `color/bg/section/secondary`, радиус 8, отступ 40, gap 24. Заголовок раздела — `typography/section/title`.
3. **Карточки:** заливка `color/bg/section/main` (для инверсии — `color/bg/section/inverse-main`), радиус 8, отступ 32, gap 32. Заголовок карточки — `typography/section/default` (`color/static/text/base/hard`), пояснение — `typography/content/body/default` (`color/static/text/base/firm`).
4. **Списки** (состояния, focus по размерам): карточка с заголовком и пунктами «подпись + экземпляр». Подпись — `typography/content/body/default`.
5. **Типовой набор разделов:** Вид / Тип (оси формы и цвета) → Размер → Содержание (варианты контента) → Загрузка (Skeleton блока и Loading действия, если у компонента есть содержимое или действия) → Corner Case (длинный текст) → Focus → Взаимодействие (Mouse / Keyboard) или Состояния → Инверсия (если есть ось Inverse).
6. Тексты разделов и пояснения — на русском. Экземпляры берутся из собранных наборов, контент — осмысленный пример («Сохранить изменения»).

## 4. Формат `presets/{component}.build.json`

```jsonc
{
  "component": "button", "title": "Button", "page": "Components / Button",
  "icons": { "default": "circle" },
  "sets": [{
    "name": "Button / Filled", "description": "…",
    "axes": [{ "name": "Size", "values": ["XL","L","M","S"] }, …],
    "exclude": [{ "State": "Disabled", "Loading": "True" }],
    "grid": { "columns": "Type", "blocks": "Size", "rows": ["Loading", "State"] },
    "vars": {                              // подстановки в имена токенов: {s}, {t}, {st}
      "s":  { "from": "Size",  "case": "lower" },
      "t":  { "from": "Type",  "case": "lower", "map": { "Inverse-primary": "inverse" } },
      "st": { "from": "State", "case": "lower" }
    },
    "props": [{ "name": "Label", "type": "TEXT", "default": "Действие" }, …],
    "root": { …шаблон слоя… }
  }],
  "spec": { "title": "Спецификация", "columns": [ … ] }
}
```

Шаблон слоя: `type` (`frame` | `text` | `rect` | `icon` | `instance`), `name`, `when` (условие по осям), `layout` (dir, gap, px, py, pt, pb, pl, pr, align, counter, w, h), `size` (w, h, minW, maxW — токены), `radius`, `fill`, `stroke` ({ color, weight, align }), `opacity`, `abs` (absolute: `focus`, `center`, `stretch-x`), `visible`, `refs` (visible → Boolean, characters → Text, mainComponent → Instance swap), `text` ({ chars, style, fill, truncate }), `icon` ({ name, size, color }), `instance` ({ set, variant, props }), `children`. Значение со словарём `{ "Size": { "XL": …, "S": … } }` выбирается по оси.
