# ТЗ: плагин «FEDS» для рабочей дизайн-системы FEroom

## 1. Назначение и границы

Плагин добавляет в уже работающую дизайн-систему в Figma новые компоненты и блоки: токены, стили, документацию, спецификацию и сам мастер-компонент. Структура токенов и логика зависимостей — как в исходном файле: `1. Primitives` → `2. General` → `3. Components`.

**Делает:**
- читает существующую систему;
- дописывает недостающие токены компонента;
- создаёт документацию и спецификацию;
- собирает компонент или блок.

**Не делает:**
- не создаёт систему с нуля и не генерирует уровни 1–2 целиком;
- не переименовывает существующее (только по запросу и в будущем);
- не меняет стиль имён (только по запросу и в будущем);
- не настраивает типографику с нуля (только по запросу и в будущем);
- не выбирает сценарии для пустого файла (только по запросу и в будущем).

## 2. Исходные условия

- Файл с системой: коллекции `1. Primitives`, `2. General` (режимы light/dark), `3. Components`. Имена коллекций настраиваются.
- Структура и соглашения как в примере:
  - в `2. General` лежат и семантика, и размеры компонентов (`size/badge/*`, `space/field/*`, `typography/button/*`);
  - инверсия задаётся токенами `inverse-*`;
  - имена в kebab-case;
  - ссылки идут только вниз: L3 → L2 → L1.
- Токены создаются только в файле-источнике библиотеки. Компонент можно собирать и в другом файле.

## 3. Сценарий работы (мастер)

1. Анализ файла.
2. Выбор компонента или блока.
3. Токены.
4. Документация.
5. Спецификация.
6. Сборка.
7. Отчёт.

Любой шаг можно пропустить. Например, только токены или только сборка по уже существующим токенам.

## 4. Функции

### F1. Анализ системы
- Сканирует коллекции, режимы, переменные, текстовые и эффект-стили, существующие компоненты и иконки.
- Строит словарь L1/L2: роли, emphasis, состояния, шкалы размеров, семейства типографики, пары `inverse-*`.
- Распознаёт соглашения файла: разделители, порядок сегментов, codeSyntax, scopes.
- Выдаёт отчёт о проблемах: битые алиасы, ссылки через уровень, дубли, переменные без scopes. Ничего не исправляет без команды.

### F2. Описание компонента (вход)
- Каталог-пресет в JSON: оси вариантов, состояния, размеры, части (bg, border, text, icon…), матрица «вариант → семантика», служебные токены, анатомия для Figma, свойства компонента.
- Импорт: JSON-пресет или MD-документ компонента (структура — как в `docs/components-source`).
- Редактор в плагине: оси, части, матрица, размеры, свойства.
- Проверка: имена по регулярке сегмента и ссылки только на существующий L2.

### F3. Токены компонента
- Генерация уровня 3 по формуле старой структуры: `{component}/{variant…}/{part}/{state}` и размеры `{component}/size/{s}/{prop}`. Каждый токен — алиас на `2. General`.
- Режим дописывания (обязательный):
  - перед записью показывается дифф: добавится / уже есть и совпадает / есть, но другая ссылка / лишний;
  - существующее меняется и удаляется только по отдельному подтверждению;
  - повторный запуск не создаёт дублей.
- Если не хватает уровня 2:
  - плагин предлагает добавить токен в `2. General` по грамматике файла (например, `size/{component}/*`), с выбором примитива;
  - уровень 1 не меняется никогда;
  - ссылка на L1 в обход L2 допустима только как явное исключение с пометкой в документации.
- Инверсия — пары `inverse-*`, как в исходной структуре.
- Для каждой переменной: scopes по типу свойства, codeSyntax (WEB), описание.
- Проверка контраста по реальным значениям в light/dark: ≥ 4,5 для текста и ≥ 3 для графики и обводок. Нарушение — предупреждение с предложением замены.

### F4. Стили
- Текстовые и эффект-стили создаются только если компоненту они нужны и в файле их нет.
- Стили привязываются к переменным `2. General`.
- Существующие стили используются повторно.

### F5. Документация
- Контракт в Markdown: назначение, анатомия, оси и состояния; таблица токенов «токен → ссылка L2 → значение light/dark»; исключения; доступность (роли ARIA, клавиатура); решения и изменения; экспорт файлом.
- Документ в Figma: страница или фрейм с описанием, правилами «использовать / не использовать», примерами. Описание компонента заполняется в `description`.

### F6. Спецификация
- Фрейм рядом с компонентом, на живых экземплярах.
- Разделы: анатомия с выносками, размеры, отступы и gaps, состояния, варианты, инверсия, содержимое (иконки, длинный текст).
- Аннотации показывают имена токенов на элементах.

### F7. Сборка компонента
- Component set: варианты по осям (только существующие ячейки матрицы, лимит — 400 на набор; при превышении набор делится по оси); имена свойств и значений в Title Case; свойства: Boolean для содержимого, Text, Instance swap для иконок и слотов, вложенные ↳.
- Слои и отступы: auto layout (направление, hug/fill, min/max); все цвета, отступы, радиусы, размеры и типографика привязаны к переменным. Ни одного захардкоженного значения.
- Вложенные элементы: существующие компоненты файла (Button, иконки, Chip) вставляются экземплярами, свойства вложенных открываются наружу.
- Приватные части (`_Field`, `_Dropdown Item`) получают префикс `_` и не публикуются.
- Размещение: отдельная страница `Components / {Title}`. Существующие страницы не меняются, при совпадении имени добавляется суффикс.

### F8. Блоки
- Сборка из существующих компонентов файла по тем же шагам, что и F2–F7.
- Собственные токены — только для «клея»: контейнер, отступы, разделители.
- Проверка, что все вложенные компоненты есть в файле. Если чего-то нет, плагин предлагает собрать это сначала.

### F9. Отчёт и откат
- Вся запись — одна операция, отменяется одним Ctrl+Z.
- Отчёт: что создано, изменено и пропущено по токенам, стилям, страницам, вариантам; предупреждения; ссылка «перейти к компоненту».

## 5. Нефункциональные требования
- Безопасность данных: существующее без подтверждения не изменяется и не удаляется; идемпотентность.
- Производительность: `documentAccess: dynamic-page`, асинхронные API; тысячи переменных без зависаний, есть индикатор прогресса.
- Совместимость: работает на тарифе Pro; не использует возможностей, недоступных на этом тарифе. Лимиты режимов проверяются заранее.
- Сеть: не нужна. Внешние ресурсы, например полная коллекция иконок, — только по явному выбору.
- Интерфейс: стиль Figma UI3, светлая и тёмная тема, русский язык интерфейса и документации, код и имена токенов — на английском.

## 6. Вход и выход
- Вход: файл с системой; пресет или MD-документ компонента; конфиг соглашений (имена коллекций, формулы имён).
- Выход: переменные L3 и, при необходимости, L2 в существующих коллекциях; стили; страница с компонентом и спецификацией; контракт `.md`; отчёт.

## 7. Критерии приёмки
1. Повторный запуск на том же компоненте не создаёт ни одной новой переменной, стиля или страницы.
2. У собранного компонента 100 % визуальных значений привязаны к переменным; смена режима light/dark на фрейме перекрашивает его корректно.
3. Все токены L3 ссылаются на `2. General`, кроме помеченных исключений. Битых алиасов 0.
4. Контракт и спецификация совпадают с фактически созданными токенами и вариантами.
5. Отмена одним Ctrl+Z возвращает файл в исходное состояние.
6. Блок собирается только из существующих компонентов файла, без копий.
