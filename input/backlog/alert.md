# Alert
Alert — сообщение внутри содержимого: в форме, карточке, панели, шаге мастера, вкладке. Оно стоит в потоке рядом с тем, о чём говорит, и занимает ширину своего контейнера. Alert объясняет состояние конкретного блока, а не всей страницы.

Документа пользователя по Alert нет: текст написан по WAI-ARIA APG (`alert`, `status`), WCAG 2.2 (4.1.3 Status Messages, 3.3.1 Error Identification, 3.3.3 Error Suggestion, 1.4.1 Use of Color), практике Material 3, Carbon, Atlassian, Polaris, Primer и шаблону error summary GOV.UK. Свои числа и решения собраны в разделе «Решения для согласования». (docs-writer 20.09.2026)

💡
Alert не заменяет Validation Message в Field. Ошибка конкретного поля живёт в Field, рядом с полем. Alert над формой — это **сводка**: что случилось со всей отправкой и к каким полям перейти.

## Пять компонентов сообщений: когда что
| **Задача** | **Компонент** |
|:--|:--|
| Короткое пояснение к элементу по наведению и фокусу, без интерактива | Tooltip |
| Панель по клику: произвольный контент, ссылки, поля, до двух действий | Popover |
| Сообщение обо всей странице или разделе, на всю ширину контейнера | Banner |
| **Сообщение о конкретном блоке контента или форме, в потоке** | **Alert** |
| Обучающая подсказка: онбординг, тур по интерфейсу | Hint |
| Короткое уведомление о результате действия, исчезает само | Toast |
| Задача, которая требует ответа и блокирует работу | Modal |
| Ошибка конкретного поля | Validation Message в Field |

### Alert и Banner
| **Что** | **Alert** | **Banner** |
|:--|:--|:--|
| Область действия | Блок: форма, карточка, панель, шаг мастера | Страница, приложение, крупный раздел |
| Ширина | По ширине контейнера-блока | По ширине страницы или раздела |
| Скругление | Всегда есть | Есть только у варианта Inset |
| Сколько одновременно | По одному на блок, блоков может быть несколько | Один на страницу |
| Закрепление при прокрутке | Нет | Возможно для системного сообщения |
| Типичная причина | Результат проверки формы, состояние данных в карточке | Состояние сервиса, режима, тарифа |

### Alert и Toast
Alert остаётся на экране и его можно перечитать; Toast исчезает сам. Всё, что пользователю нужно для исправления ошибки, живёт в Alert, а не в Toast.

Уведомление поверх интерфейса собирается из Alert вида Default или Bold в группе уведомлений (у Atlassian — Flag и Flag group). Toast пока не закладывается (решение автора 21.09.2026). *(дополнено 21.09.2026 по композиции Atlassian Flag)*

## Вид (Appearance)
*(добавлено 21.09.2026: композиция по Atlassian Flag и Section message; токены — текущая система FEroom)*

| **Вид** | **Аналог** | **Где** | **Закрытие** | **Действия** | **Раскрытие** |
|:--|:--|:--|:--|:--|:--|
| Subtle | Section message | В потоке блока: форма, карточка, панель | Да, кроме Error | Button Outline + Text | Нет |
| Default | Flag (default) | Уведомление о событии поверх интерфейса, в группе | Да | Ссылки (Button Text Primary и Secondary) | Нет |
| Bold | Flag (bold) | Важное уведомление: успех, предупреждение, ошибка, загрузка | Нет, пока причина не устранена | Кнопки Text · Inverse (на жёлтом — Text · Secondary) | Свёрнут / раскрыт |

- **Subtle** — прежний Alert: тонированная подложка роли, обводка роли, иконка роли.
- **Default** — нейтральная карточка `alert/default/bg` (`color/bg/raised/main`) с рамкой `alert/default/border`; роль передаёт иконка. Для уведомлений о действиях людей иконку заменяет аватар (следующий шаг сборки: нужен Avatar).
- **Bold** — насыщенная заливка роли `alert/bold/bg/{role}` (`color/status/{hue}/bold/default`): текст и иконка белые, у Warning — тёмные (белый на жёлтом не читается). Свёрнутый Bold показывает только заголовок и шеврон; раскрытый — текст и до двух действий.
- Тень карточки Default в Figma пока не собирается: эффект-стили не проработаны. Её роль временно играет рамка.

### Группа уведомлений
- Default и Bold показываются в группе в углу экрана (снизу слева или справа — одно место на весь продукт), поверх содержимого и поверх Modal;
- Новое уведомление встаёт сверху; после закрытия поднимается следующее;
- Закрываемые (Default) и незакрываемые (Bold) в одной стопке не смешиваются;
- Warning и Error никогда не скрываются сами; Success может скрыться по таймеру, если в нём нет действий (WCAG 2.2.1: дайте время прочитать и возможность остановить);
- Длинное объяснение не помещается в уведомление: дайте ссылку на страницу или используйте Banner, Alert Subtle или Modal.

## Использовать
- Показать сводку ошибок формы после отправки;
- Объяснить, почему блок не работает: нет прав, данные устарели, лимит исчерпан;
- Предупредить о последствиях настройки, которую пользователь сейчас меняет;
- Подтвердить результат операции внутри блока («Файл проверен, 0 ошибок»);
- Объяснить состояние карточки или строки мастера перед переходом к следующему шагу.

## Не использовать
| **Задача** | **Компонент** |
|:--|:--|
| Сообщение относится ко всей странице или приложению | Banner |
| Ошибка одного поля | Validation Message в Field |
| Постоянное пояснение к элементу | Description в Field · Tooltip |
| Короткое пояснение по наведению | Tooltip |
| Результат действия, который можно не читать | Toast |
| Требуется ответ, работа блокируется | Modal |
| В блоке нет данных | Empty State |
| Статус одной сущности | Status / Badge |

## Состав
| **Элемент** | **Назначение** | **Обязателен** |
|:--|:--|:--|
| Контейнер | Поверхность сообщения: фон роли, обводка, скругление | Да |
| Иконка роли | Дублирует смысл роли не только цветом (WCAG 1.4.1) | Да |
| Заголовок | Суть в одну строку | Нет |
| Текст | Пояснение и что делать | Да |
| Список | Перечень ошибок со ссылками на поля | Нет |
| Действия | До двух: Button и/или Link; подпись говорит, куда ведёт («Права доступа», а не «Подробнее») | Нет |
| Кнопка закрытия | Скрывает сообщение (Subtle, Default) | Нет |
| Шеврон раскрытия | Сворачивает и раскрывает текст и действия (Bold) | У Bold |

## Размеры
Alert поддерживает два размера. Размер выбирается по плотности окружения, а не по важности сообщения.

| **Размер** | **Где применять** |
|:--|:--|
| S | Плотное окружение: карточка, строка таблицы, боковая панель, popover |
| M | Стандартный размер: форма, шаг мастера, основная колонка контента |

| **Свойство** | **S** | **M** | **Токен уровня 2** |
|:--|:--|:--|:--|
| Заголовок | 12 / 16, 600 | 14 / 20, 600 | `typography/heading/overline` · `typography/heading/group` |
| Текст | 12 / 16, 400 | 14 / 20, 400 | `typography/helper/default` · `typography/body/ui` |
| Иконка роли | 16 | 20 | `size/icon/m` · `size/icon/l` |
| Внутренний отступ | 12 (решение, токена нет) | 16 | см. «Решения для согласования» · `space/message/padding` |
| Иконка ↔ текст | 8 | 12 | `space/inline/default` · `space/message/icon-gap` |
| Заголовок ↔ текст | 4 | 4 | `space/stack/tight` |
| Текст ↔ действия | 4 | 8 | `space/stack/tight` · `space/stack/default` |
| Контент ↔ кнопка закрытия | 8 | 8 | `space/inline/default` |
| Скругление | 6 | 8 | `radius/control/m` · `radius/control/l` |
| Обводка роли | ≥ 3 : 1 к фону | ≥ 3 : 1 к фону | `color/static/border/{role}/default` |

Высота растёт по содержимому: Alert многострочный, текст переносится и никогда не обрезается многоточием.

## Содержимое
- Заголовок нужен, когда текста больше одной строки или в сообщении есть список;
- Текст — до 3 строк; длинное объяснение выносится по ссылке «Подробнее»;
- Формулировка по WCAG 3.3.1 и 3.3.3: что именно не так и как это исправить;
- В сводке ошибок каждая строка — ссылка на поле; клик переводит фокус в это поле;
- Не дублируйте одно сообщение в Alert и в Validation Message поля: в сводке — перечень, у поля — подробность (`field.md`: одно сообщение не повторяется в Description и Validation Message);
- Не используйте в тексте слова «здесь», «выше», «ниже»: сообщение читают отдельно от макета;
- Действий не больше двух.

## Состояния
У Alert нет Hover, Pressed и Disabled: состояния принадлежат кнопкам и ссылкам внутри.

| **Состояние** | **Когда** | **Поведение** |
|:--|:--|:--|
| Visible | Причина сообщения существует | Alert в потоке, занимает место в блоке |
| Dismissed | Пользователь закрыл сообщение | Alert убирается; при повторении причины показывается снова |
| Updated | Текст сообщения изменился | Live-region объявляет новое сообщение; если текст тот же, повторно не объявляется |

Alert не исчезает сам (WCAG 2.2.1) и не закрывается при клике по странице.

## Варианты и роли
| **Роль** | **Когда** | **Пример** |
|:--|:--|:--|
| Info | Нейтральное пояснение к блоку | «Изменения применятся после сохранения» |
| Success | Операция внутри блока завершилась успешно | «Файл проверен: 412 строк, 0 ошибок» |
| Warning | Есть риск, работа продолжается | «У двух участников нет доступа к проекту» |
| Danger | Ошибка, действие не выполнено | «Форму не удалось отправить: проверьте 3 поля» |

- Роль передаётся иконкой, цветом и текстом (WCAG 1.4.1);
- Оформление по ролям то же, что у Banner: фон `color/layer/card/{role}/subtle`, обводка `color/static/border/{role}/default`, иконка `color/static/icon/{role}/default`, текст `color/static/text/neutral/primary`;
- Кнопка закрытия допустима у Info и Success. Danger, который объясняет незавершённое действие, закрывать нельзя: сообщение исчезает после исправления;
- Роль сообщения и состояние валидации Field — разные вещи: Field Error оформляет поле, Alert danger объясняет отправку.

## Поведение
| **Событие** | **Что происходит** |
|:--|:--|
| Форма отправлена с ошибками | Alert danger появляется над формой, фокус переводится на его контейнер, сообщение объявляется |
| Пользователь исправил поля и отправил снова | Alert обновляется или убирается; если ошибки остались, объявляется новый текст |
| Alert появился при загрузке блока | Сообщение читается в обычном порядке документа, live-region не нужен |
| Alert появился в ответ на действие | Объявляется: danger — *role="alert"*, остальные роли — *role="status"* |
| Пользователь нажал «Закрыть» | Сообщение убирается, фокус переходит на следующий элемент блока |
| Причина исчезла | Alert убирается без отдельного уведомления |
| Несколько сообщений в одном блоке | Показывается одно, по приоритету danger → warning → success → info |

Место размещения:
- Сводка ошибок формы — над первым полем формы, внутри её контейнера;
- Сообщение о блоке — сразу под заголовком блока, до содержимого;
- Сообщение о шаге мастера — над содержимым шага;
- Alert не ставится в футер формы рядом с кнопкой отправки: после отправки страница может прокрутиться, и сообщение останется за кадром.

## Regular и Inverse
| **Режим** | **Где применять** |
|:--|:--|
| Regular | Светлые и стандартные поверхности |
| Inverse | Тёмные поверхности: Alert наследует режим фрейма, отдельного варианта нет |

Alert и контрол, к которому он относится, используют один режим внутри одного блока.

## Доступность (A11y)
- **Сообщение об ошибке, появившееся в ответ на действие, получает *role="alert"*** (assertive live-region): оно прерывает чтение, потому что действие не выполнено;
- **Нейтральное сообщение (info, success, warning) получает *role="status"*** (polite, WCAG 4.1.3): оно дочитывается после текущей фразы;
- **Alert, отрисованный вместе со страницей, роли live-region не получает**: иначе он прозвучит дважды;
- Контейнер live-region существует в DOM до появления текста;
- Сводка ошибок формы: контейнер получает `tabindex="-1"`, после неуспешной отправки фокус переводится на него, ошибки перечислены ссылками на поля (шаблон error summary GOV.UK);
- Поля с ошибкой помечаются *aria-invalid="true"*, а их текст ошибки связывается через *aria-describedby* (это задача Field);
- Иконка роли декоративна: *aria-hidden="true"*;
- Кнопка закрытия получает доступное имя «Закрыть», зона нажатия не меньше 24 × 24 (WCAG 2.5.8);
- Контраст текста ≥ 4,5 : 1, иконки и обводки ≥ 3 : 1 (WCAG 1.4.3, 1.4.11);
- Цвет не единственный носитель смысла (WCAG 1.4.1);
- Одно и то же сообщение не объявляется одновременно Alert и Toast;
- Заголовок уведомления (Default, Bold) — заголовок уровня h2: по нему навигирует экранный диктор;
- Шеврон Bold — кнопка с `aria-expanded` и доступным именем «Показать подробности» / «Скрыть подробности»;
- Роль не передаётся только цветом заливки Bold: иконка и текст обязательны.

## Управление клавиатурой
| **Действие** | **Результат** |
|:--|:--|
| Tab | Фокус проходит по ссылкам и действиям сообщения в порядке чтения |
| Enter / Space на действии | Выполняет действие |
| Enter на ссылке в сводке ошибок | Переводит фокус в поле с ошибкой |
| Enter / Space на кнопке закрытия | Закрывает сообщение, фокус переходит дальше по блоку |
| Escape | Ничего не делает: Alert — часть страницы, а не оверлей |

Контейнер Alert не является Tab-остановкой; исключение — сводка ошибок, куда фокус переводится программно.

## Делать
- Ставить Alert рядом с тем, о чём он говорит;
- Писать, что произошло и что делать;
- Переводить фокус на сводку ошибок после неуспешной отправки;
- Делать ссылки из сводки на поля с ошибкой;
- Убирать сообщение, когда причина исчезла.

## Не делать
- Не заменять Alert'ом сообщение об ошибке поля;
- Не повторять один и тот же текст в сводке и у поля;
- Не закрывать Alert по таймеру;
- Не ставить Alert поверх содержимого — он в потоке;
- Не показывать несколько сообщений об одном и том же;
- Не полагаться только на цвет роли;
- Не давать кнопку закрытия у сообщения о несохранённой ошибке.

## Связанные компоненты
| **Компонент** | **Когда использовать** |
|:--|:--|
| Banner | Сообщение уровня страницы или раздела |
| Toast | Короткое уведомление о результате действия |
| Field | Label, Description и Validation Message поля |
| Modal | Требуется ответ, работа блокируется |
| Empty State | В блоке нет данных |
| Status, Badge | Статус одной сущности |
| Button, Link | Действия внутри сообщения |
| Hint | Обучающая подсказка: онбординг, тур по интерфейсу |

# Решения для согласования (docs-writer 20.09.2026)
1. **Два размера, S и M.** S — для карточек, боковых панелей и popover; M — стандарт формы. Размер выбирается по плотности окружения, а не по важности сообщения. Шаги типографики и иконок совпадают с шагами `field.md` для S и M.
2. **Размер M закрыт, размер S — открытый вопрос.** ds-architect 20.09.2026 завёл общие с Banner `space/message/{padding,icon-gap}` = 16 · 12: это Alert M. Для компактного Alert S нужен второй шаг — `space/message/padding-compact` = 12 и `icon-gap-compact` = 8. Альтернатива: отказаться от размера S и в плотных местах (карточка, popover, строка таблицы) использовать обычный поясняющий текст. Решение — за ds-architect и пользователем.
3. **Фон — `color/layer/card/{role}/subtle`, у Banner — `color/layer/page/{role}/subtle`.** Alert чаще лежит на карточке, Banner — на странице. Если ds-architect решит, что слой определяется местом, а не компонентом, ссылка станет одинаковой.
4. **Роли те же четыре, что у Banner и Status: info · success · warning · danger.** Роль `brand` не используется.
5. **`role="alert"` только для danger, появившегося в ответ на действие; для info, success и warning — `role="status"`.** Warning не прерывает чтение: работа продолжается.
6. **Alert, отрисованный вместе со страницей, live-region не получает.** Иначе screen reader прочитает сообщение дважды.
7. **Сводка ошибок формы — сценарий Alert danger, а не отдельный компонент.** Контейнер получает `tabindex="-1"`, после неуспешной отправки на него переводится фокус, внутри — ссылки на поля (шаблон GOV.UK). Отдельный компонент Error Summary предлагается не заводить.
8. **Alert не закрывается сам** (WCAG 2.2.1) и не получает кнопку закрытия в роли danger.
9. **В каталоге Alert остаётся `interactive: false`**: состояния принадлежат вложенным Button и Link.
10. **Alert расширен до трёх видов по композиции Atlassian Flag** (21.09.2026): Subtle (в потоке), Default (карточка-уведомление), Bold (насыщенный, сворачивается). Компонент один, вид — свойство Appearance.
11. **Toast пока не закладывается** (решение автора 21.09.2026). Уведомление поверх интерфейса — Alert Default или Bold в группе уведомлений; группа — блок (F8) из экземпляров Alert.
12. **Для Bold добавлены L2 `color/status/{hue}/bold/*`**: существующие `status/*/medium` в light дают белому тексту 3,8–4,1 : 1 и остаются за Badge и Status до решения по их палитре. Warning Bold — тёмный текст.
13. **Действия — кнопки системы; на тёмной поверхности и на заливке Bold — тип Inverse** (решение автора 21.09.2026). Subtle: Outline Secondary + Text Secondary, на тёмной поверхности — Outline Inverse + Text Inverse. Default: ссылки Text Primary + Text Secondary, на тёмной — Text Inverse. Bold: Text Inverse, шеврон — Icon Only Inverse-primary; на жёлтой заливке Warning белое не проходит WCAG, там Text Secondary и Icon Only Secondary. Своих кнопок и токенов кнопок у Alert нет. Заливка Bold одинакова в обеих темах, поэтому Bold закрепляет светлую тему `2. General` (в коде — `data-theme="light"` на плашке): инверсные кнопки внутри всегда светлые.
