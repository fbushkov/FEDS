# Banner
Banner — сообщение уровня страницы или крупного раздела. Он занимает всю ширину своего контейнера, стоит в потоке сверху и остаётся на экране, пока причина сообщения не исчезла. Баннер сообщает о состоянии системы или условиях работы, а не о результате отдельного действия.

Документа пользователя по Banner нет: текст написан по WAI-ARIA APG (`alert`, `status`), WCAG 2.2 (4.1.3 Status Messages, 2.2.1 Timing Adjustable, 1.4.1 Use of Color) и практике Material 3, Carbon, Atlassian, Polaris, Primer, GOV.UK. Свои числа и решения собраны в разделе «Решения для согласования». (docs-writer 20.09.2026)

💡
Баннер говорит о **контексте**: сервис недоступен, включён режим только для чтения, действует тестовый период, данные устарели. Сообщение о результате конкретного действия — это Toast, а сообщение о конкретном блоке или форме — Alert.

## Пять компонентов сообщений: когда что
| **Задача** | **Компонент** |
|:--|:--|
| Короткое пояснение к элементу по наведению и фокусу, без интерактива | Tooltip |
| Панель по клику: произвольный контент, ссылки, поля, до двух действий | Popover |
| **Сообщение обо всей странице или разделе, на всю ширину контейнера** | **Banner** |
| Сообщение о конкретном блоке контента или форме, в потоке | Alert |
| Обучающая подсказка: онбординг, тур по интерфейсу | Hint |
| Короткое уведомление о результате действия, исчезает само | Toast |
| Задача, которая требует ответа и блокирует работу | Modal |
| Ошибка конкретного поля | Validation Message в Field |

### Banner, Alert и Toast
| **Что** | **Banner** | **Alert** | **Toast** |
|:--|:--|:--|:--|
| Область действия | Страница, приложение, крупный раздел | Блок контента, форма, карточка | Результат действия пользователя |
| Место | Сверху страницы или раздела, во всю ширину | В потоке рядом с тем, о чём говорит | Плавающий слой над интерфейсом |
| Время жизни | Пока причина не исчезла | Пока причина не исчезла | Несколько секунд |
| Закрытие | Пользователем, если сообщение не блокирующее | Пользователем, если сообщение не об ошибке | Само, плюс кнопка закрытия |
| Действия | До двух, в том числе переход на другую страницу | До двух, рядом с сообщением | Одно, короткое («Отменить») |
| Прокрутка | Уезжает со страницей или закрепляется сверху | Уезжает со страницей | Не зависит от прокрутки |

## Использовать
- Сообщить о недоступности или деградации сервиса, плановых работах;
- Предупредить об окончании тестового периода, лимита, срока действия доступа;
- Сообщить, что раздел работает в режиме только для чтения;
- Показать последствия глобальной настройки («показаны архивные данные»);
- Сообщить об успехе длинной операции, результат которой виден на всей странице (импорт завершён);
- Показать одно важное объявление о продукте, которое можно закрыть.

## Не использовать
| **Задача** | **Компонент** |
|:--|:--|
| Сообщение относится к одному блоку, карточке или форме | Alert |
| Результат действия, который можно не читать | Toast |
| Ошибка конкретного поля | Validation Message в Field |
| Пояснение к элементу | Tooltip · Description в Field |
| Требуется ответ, работа блокируется | Modal |
| В разделе нет данных | Empty State |
| Статус одной сущности в строке или таблице | Status / Badge |
| Реклама и промо на полстраницы | Маркетинговый блок, не компонент системы |

## Состав
| **Элемент** | **Назначение** | **Обязателен** |
|:--|:--|:--|
| Контейнер | Поверхность сообщения: фон роли, обводка, скругление | Да |
| Иконка роли | Дублирует смысл роли, не только цветом (WCAG 1.4.1) | Да |
| Заголовок | Суть сообщения в одну строку | Нет |
| Текст | Пояснение и что делать дальше | Да |
| Действия | До двух: Button и/или Link | Нет |
| Кнопка закрытия | Скрывает сообщение | Нет |

Порядок слева направо: иконка → текст-блок (заголовок, текст, действия) → кнопка закрытия.

## Размеры
У Banner один размер: он всегда занимает ширину контейнера, а высота растёт по содержимому.

| **Свойство** | **Значение** | **Токен уровня 2** |
|:--|:--|:--|
| Заголовок | 14 / 20, 600 | `typography/heading/group` |
| Текст | 14 / 20, 400 | `typography/body/ui` |
| Иконка роли | 20 | `size/icon/l` |
| Внутренний отступ | 16 | `space/message/padding` |
| Иконка ↔ текст | 12 | `space/message/icon-gap` |
| Заголовок ↔ текст | 4 | `space/stack/tight` |
| Текст ↔ действия | 8 | `space/stack/default` |
| Контент ↔ кнопка закрытия | 8 | `space/inline/default` |
| Обводка роли | ≥ 3 : 1 к фону | `color/static/border/{role}/default` |
| Скругление (вариант Inset) | 12 | `radius/card` |
| Скругление (вариант Full bleed) | 0 | — |
| Слой (закреплённый баннер) | 1200 | `z-index/banner` |

### Варианты по ширине
| **Вариант** | **Где применять** | **Оформление** |
|:--|:--|:--|
| Full bleed | Сверху страницы или приложения, от края до края | Без скругления и боковой обводки, отделяется нижней границей |
| Inset | Внутри раздела, в колонке контента | Скругление 12, обводка по периметру |

## Содержимое
- Заголовок — до 1 строки, без точки; если сообщение умещается в одну фразу, заголовок не нужен;
- Текст — до 3 строк; баннер многострочный, текст переносится и не обрезается многоточием;
- Сообщение отвечает на два вопроса: что произошло и что делать;
- Действий не больше двух; основное — первое;
- Не пишите «Ошибка» или «Внимание» вместо содержания: роль уже несёт иконка и цвет;
- Текст не повторяет заголовок другими словами;
- Даты, сроки и суммы пишите явно: «до 30 сентября», а не «скоро».

## Состояния
У Banner нет Hover, Pressed и Disabled: состояния принадлежат кнопкам и ссылкам внутри.

| **Состояние** | **Когда** | **Поведение** |
|:--|:--|:--|
| Visible | Причина сообщения существует | Баннер в потоке, занимает место |
| Dismissed | Пользователь закрыл сообщение | Баннер убирается; правило повторного показа задаёт продукт |
| Sticky | Сообщение должно быть видно при прокрутке | Баннер закрепляется сверху, слой `z-index/banner` |

Баннер **не исчезает сам**: у него нет таймера (WCAG 2.2.1). Он пропадает только тогда, когда пропала причина, или когда пользователь его закрыл.

## Варианты и роли
| **Роль** | **Когда** | **Пример** |
|:--|:--|:--|
| Info | Нейтральное сообщение о контексте | «Показаны архивные данные за 2025 год» |
| Success | Длинная операция завершилась, результат виден на странице | «Импорт завершён: добавлено 412 записей» |
| Warning | Есть риск или ограничение, работа продолжается | «Тестовый период заканчивается 30 сентября» |
| Danger | Что-то сломано или заблокировано, нужно действие | «Сервис оплаты недоступен, платежи не проходят» |

- Роль передаётся тремя средствами: иконка, цвет фона и текст. Цвет не единственный носитель смысла (WCAG 1.4.1);
- Роли `brand` у баннера нет: фирменный фон делает сообщение рекламой;
- Оформление: фон `color/layer/page/{role}/subtle`, обводка `color/static/border/{role}/default`, иконка `color/static/icon/{role}/default`, текст `color/static/text/neutral/primary`, пояснение `color/static/text/neutral/secondary`;
- Закрывать можно Info, Success и Warning. Danger, который блокирует работу, кнопки закрытия не имеет.

## Поведение
| **Событие** | **Что происходит** |
|:--|:--|
| Причина появилась при загрузке страницы | Баннер отрисован сразу, в потоке, без live-region |
| Причина появилась во время работы | Баннер вставляется сверху, контент сдвигается; сообщение объявляется screen reader |
| Пользователь нажал «Закрыть» | Баннер убирается, фокус переходит на следующий элемент или на заголовок страницы |
| Причина исчезла | Баннер убирается сам, без сообщения об этом |
| Действие в баннере | Выполняется; если оно устраняет причину, баннер убирается |
| Несколько сообщений | Одновременно показывается один баннер; при конфликте выигрывает роль: danger → warning → success → info |
| Прокрутка | Обычный баннер уезжает со страницей; системный (danger уровня приложения) может быть закреплён |

Место размещения:
- Системный баннер — под шапкой приложения, над всем содержимым, во всю ширину;
- Баннер раздела — внутри раздела, над его содержимым, но ниже заголовка раздела;
- Баннер никогда не ставится внутрь карточки или формы: там работает Alert;
- Появление баннера не должно сдвигать контент под курсором в момент нажатия.

## Regular и Inverse
| **Режим** | **Где применять** |
|:--|:--|
| Regular | Светлые и стандартные поверхности |
| Inverse | Тёмные поверхности: баннер наследует режим фрейма, отдельного варианта нет |

Роль, иконка и текст в режиме Inverse те же: меняются только значения токенов уровня 2.

## Доступность (A11y)
- **Статический баннер**, отрисованный вместе со страницей, не оборачивают в live-region: он читается в обычном порядке документа;
- **Баннер, который появился во время работы**, объявляется: роль `danger` — *role="alert"* (assertive), остальные роли — *role="status"* (polite), WCAG 4.1.3;
- Контейнер live-region существует в DOM **до** появления текста, иначе сообщение не будет объявлено;
- Баннер уровня страницы полезно оформить как `<section>` с *aria-labelledby* на заголовок: так его можно найти по ориентирам;
- Иконка роли декоративна и скрывается *aria-hidden="true"*: смысл несёт текст;
- Кнопка закрытия получает доступное имя «Закрыть» и зону нажатия не меньше 24 × 24 (WCAG 2.5.8);
- После закрытия фокус не теряется: он переводится на следующий элемент или на заголовок страницы;
- У баннера нет таймера автоскрытия (WCAG 2.2.1);
- Контраст текста ≥ 4,5 : 1, иконки и обводки ≥ 3 : 1 (WCAG 1.4.3, 1.4.11);
- Одновременно активных live-region должно быть как можно меньше: баннер, Alert и Toast не объявляют одно и то же сообщение дважды.

## Управление клавиатурой
| **Действие** | **Результат** |
|:--|:--|
| Tab | Фокус проходит по действиям баннера и по кнопке закрытия в порядке чтения |
| Enter / Space на действии | Выполняет действие |
| Enter / Space на кнопке закрытия | Закрывает баннер и переводит фокус дальше |
| Escape | Ничего не делает: баннер — часть страницы, а не оверлей |

Сам контейнер баннера не получает фокус и не является Tab-остановкой.

## Делать
- Писать, что произошло и что делать;
- Ставить баннер сверху той области, к которой он относится;
- Показывать не больше одного баннера одновременно;
- Убирать баннер, когда причина исчезла;
- Дублировать роль иконкой и текстом, а не только цветом.

## Не делать
- Не закрывать баннер по таймеру;
- Не показывать баннером результат обычного действия — это Toast;
- Не ставить баннер внутрь формы или карточки — это Alert;
- Не складывать три-четыре баннера подряд;
- Не давать кнопку закрытия у сообщения, которое блокирует работу;
- Не превращать баннер в рекламный блок;
- Не полагаться только на цвет роли.

## Связанные компоненты
| **Компонент** | **Когда использовать** |
|:--|:--|
| Alert | Сообщение о блоке контента или форме |
| Toast | Короткое уведомление о результате действия |
| Modal | Требуется ответ, работа блокируется |
| Empty State | В разделе нет данных |
| Status, Badge | Статус одной сущности |
| Button, Link | Действия внутри баннера |
| Hint | Обучающая подсказка: онбординг, тур по интерфейсу |

# Решения для согласования (docs-writer 20.09.2026)
1. **С Banner снят флаг `hidden: true` в `src/catalog/components.json`** — по той же причине, что и с Popover (`docs/decisions.md`, запись 19.09.2026 о временно скрытых компонентах): у компонента появился документ, на уровне 2 уже есть `color/layer/page/{role}/subtle`, `color/static/{text,icon,border}/{role}/*` и `z-index/banner` = 1200.
2. **Роли четыре: info · success · warning · danger.** Роль `brand` не используется: фирменный фон превращает сообщение в промо. Набор совпадает с ролями Alert, Status и Badge.
3. **Внутренний отступ 16, промежуток иконка ↔ текст 12 — закрыто.** ds-architect 20.09.2026 завёл `space/message/{padding,icon-gap}` = 16 · 12, общие у Banner и Alert (позже Toast). Заголовок ↔ текст — `space/stack/tight`, текст ↔ действия — `space/stack/default`, контент ↔ кнопка закрытия — `space/inline/default`. Обводка роли переведена на шаг ≥ 3 : 1 (`color/static/border/{role}/default`).
4. **Два варианта по ширине: Full bleed (радиус 0) и Inset (`radius/card` = 12).** Отдельного `radius/banner` не предлагается: у сообщения и карточки одна поверхность.
5. **Баннер не закрывается сам.** Автоскрытие противоречит WCAG 2.2.1 и смешивает Banner с Toast.
6. **Live-region зависит от момента появления:** статический баннер — без роли, появившийся во время работы — *role="status"*, а danger — *role="alert"*. Так сообщение не читается дважды при загрузке страницы.
7. **Один баннер одновременно, приоритет danger → warning → success → info.** Стек баннеров отклонён: он съедает верх экрана и обесценивает сообщения.
8. **Иконка роли обязательна** — это второй носитель смысла помимо цвета (WCAG 1.4.1).
9. **В каталоге Banner остаётся `interactive: false`**: состояния принадлежат кнопкам и ссылкам внутри сообщения.
