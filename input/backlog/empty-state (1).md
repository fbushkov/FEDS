# Empty State

### Общие принципы


1. Empty State центрируется по контентной области (не по всему экрану, не в углу).
2. Каждое пустое состояние = смысл + действие, а не констатация "Нет данных".
3. Один визуальный язык для всех разделов (иконка, типографика, отступы, кнопки).
4. При появлении первой сущности состояние исчезает мгновенно (в лучшем случае с быстрой анимацией исчезновения появления сущностей).
5. Разделять причины пустоты (нет данных, фильтр, загрузка, ошибка, нет прав).

### 1. Страница или таблица без сущностей

Когда данных нет вообще, пользователь впервые в разделе. Размещать в центр контентной области, отступ сверху \~15–20% высоты. Шапку таблицы (колонки) скрывать. Контент:

* Иллюстрация/иконка (64px)
* Заголовок "У вас пока нет {сущности}"
* Подзаголовок в одну–две строки (как объяснение)
* Кнопка Primary "Создать {сущность}"
* Опционально вторичные действия "Импорт", "Из шаблона", "Как это работает"

### 2. Таблица или список —  поиск или фильтр ничего не нашёл

Когда данные есть, но не подходят под запрос. Размещать в центр области списка. Шапку таблицы (колонки) и панель фильтров/поиск оставить. Контент:

* Иконка поиска (48px)
* Заголовок "ничего не нашлось"
* Подзаголовок "По запросу "{текст}" ничего нет, измените запрос или фильтры"
* Secondary CTA "Сбросить фильтры" или "Очистить поиск"
* Без кнопки "Создать сущность"

### 3. Пустой блок, виджет или вкладка внутри заполненной страницы

Карточка или панель или вкладка без контента (связи, комментарии, вложения). азмещать в центр самого блока. Компактный формат. Контент:

* Малая иконка (32px) или без неё
* Короткий заголовок "{Сущность} пока недоступна"
* Одна строка подсказки
* Компактная secondary-кнопка (если действие в руках пользователя)
* Без кнопки, если действие зависит от других (инфо-вариант)

### 4. Контент загружается или ещё формируется

Данные будут, но обрабатываются (видео, расшифровка, отчёт) Размещать внутри блока, где появится контент. Тут в целом пунктирная рамка (placeholder) допустима. Контент:

* Иконка типа контента
* Заголовок "{Контент} загружается" или "{Контент} пока недоступен"
* Подзаголовок "Здесь появится {что} после {условие}"
* CTA disabled, если действие зависит от условия (например "Сформировать" неактивна до загрузки записи)
* Опционально индикатор загрузки, статуса

### 5. Ошибка загрузки данных

Когда запрос не выполнился (сеть, сервер). Размещать в центр области, где ожидались данные. Контент:

* Иконка ошибки (48px)
* Заголовок: "Не удалось загрузить {сущность}"
* Подзаголовок: причина, что делать (в лучшем случае)
* Primary CTA "Повторить"

### 6. Нет прав доступа

Когда сущность есть, но пользователю закрыта. Размещать в центр области. Контент:

* Иконка замка (48px)
* Заголовок: "Нет доступа к {разделу}"
* Подзаголовок к кому обратиться
* CTA "Запросить доступ" (если применимо)

### 7. Всё выполнено или очищено

Когда данные были, но закончились естественным образом, всё сделано, просмотрено, разобрано. Размещать в центр области списка. Контент:

* Позитивная иконка (галочка)
* Заголовок "Всё готово" / "Задач нет"
* Подзаголовок в одну строку вроде "все задачи выполнены"
* CTA опционально

### 8. Дашборд, аналитика без данных

Когда нет данных для графиков/метрик. Размещать внутри каждого виджета отдельно. Контент:

* Заглушка графика (серый placeholder) или иконка
* Заголовок "Пока нет данных"
* Подзаголовок когда появятся и что для этого нужно

### 9. Контейнер с фиксированной панелью действий (панели, модалки, drawer'ы)

Если у контейнера есть постоянный action-бар с кнопкой создания:

* Кнопка остаётся в action-баре в обоих состояниях (пустом и заполненном) — позиция и стиль не меняются.
* Empty state внутри контейнера — информационный (по сценарию 3) — иконка, заголовок, подзаголовок, отсылающий к кнопке ниже.
* CTA внутри empty state **не дублируется**.
* Запрещено: кнопка меняет позицию/стиль (secondary — primary) при появлении первой сущности.

### После появления первой сущности


1. Empty State исчезает сразу, появляется строка/контент.
2. Один элемент = обычный список с шапкой
3. Удаление всех элементов = возврат к Сценарию 1 или 7.
4. Onboarding-подсказки показывать как tooltip, а не как Empty State.
