# Combobox
Combobox — поле, в которое пользователь вводит текст, а Dropdown под ним показывает только подходящие варианты. Значение выбирается из отфильтрованного списка. Если сценарий это разрешает, можно ввести своё значение или создать новое.

Компонент состоит из двух частей:
| **Часть** | **Назначение** |
|:--|:--|
| Поле Combobox | Принимает ввод, показывает выбранное значение, открывает / закрывает список |
| Dropdown | Отфильтрованный список вариантов — см. `dropdown.md` |

💡
Label, Description и текст валидации относятся к обертке поля — Field.

## Использовать
- Вариантов много: больше, чем удобно просматривать в Select (ориентир из `select.md` — больше 25);
- Пользователь знает, что ищет, и быстрее напечатать, чем листать: город, сотрудник, код, справочник;
- Список загружается с сервера по запросу;
- Нужно выбрать из списка или ввести своё значение (когда разрешено свободное значение);
- Нужно выбрать существующий тег или создать новый.

## Не использовать
| **Задача** | **Компонент** |
|:--|:--|
| До 25 вариантов, поиск не нужен | Select |
| До 5 вариантов, которые полезно видеть сразу | Radio / Segmented Control |
| Можно выбрать несколько значений | Multiselect |
| Произвольный текст без списка вариантов | Input |
| Поиск по контенту страницы или разделу, а не выбор значения | Search Input |

## Размеры
Combobox, Dropdown и Dropdown Item поддерживают размеры S / M / L. Размер Dropdown равен размеру поля.
| **Размер** | **Где применять** |
|:--|:--|
| S | Таблицы, фильтры, плотные панели |
| M | Стандартный размер для большинства форм |
| L | Крупные формы и сценарии с повышенным визуальным приоритетом |

## Отличия от оболочки Input
Поле Combobox наследует оболочку Input (`input.md`, раздел «Оболочка поля (база семейства)»): контейнер, состояния, Placeholder / Value, Leading Zone, Clear, State Icon, Spinner. Ниже — только отличия.
| **Что** | **Input** | **Combobox** |
|:--|:--|:--|
| Chevron | Нет | Есть, последним в Trailing Zone. Открывает и закрывает список мышью |
| Open | Нет | Признак раскрытия Dropdown, существует параллельно с Focused |
| Ввод | Свободный | Ввод фильтрует список; итоговое значение — из списка или свободное, по настройке |
| Suffix, Actions | Да | Нет, кроме Clear |
| Роль ARIA | Текстовое поле | `role="combobox"` на поле ввода |

Состояния поля — как у оболочки Input: Default, Hover, Focused, Disabled, Read Only, Error, Warning, Success, Loading, плюс признак Open. Pressed не нужен: после клика поле переходит в Focused, как Input.

## Режимы автодополнения
Режим задаёт, как список и поле реагируют на ввод. Он передаётся атрибутом `aria-autocomplete`.
| **Режим** | **Что происходит при вводе** | **`aria-autocomplete`** | **Когда применять** |
|:--|:--|:--|:--|
| List | Dropdown показывает варианты, подходящие под запрос. Текст в поле не меняется | `list` | Основной режим: справочники, люди, города |
| List + inline | Как List, плюс поле дописывает первый подходящий вариант выделенным текстом | `both` | Короткие однозначные значения, которые печатают по началу: коды, теги |
| Inline | Поле дописывает вариант, списка нет | `inline` | Редко; только когда список не нужен визуально |
| None | Список не фильтруется, показывает подсказки, связанные с запросом не буквально | `none` | Недавние запросы, рекомендации |

- По умолчанию используйте **List**;
- В List + inline дописанная часть выделена, следующий символ заменяет её, Backspace удаляет её без удаления введённого;
- Режим один на весь продукт для однотипных полей.

## Значение: из списка или свободное
| **Настройка** | **Что можно сохранить** | **Пример** |
|:--|:--|:--|
| Только из списка (по умолчанию) | Только вариант из Dropdown | Город из справочника, сотрудник |
| Свободное значение | Вариант из списка или любой введённый текст | Должность с подсказками, адрес с подсказками |
| Создание | Вариант из списка или новый вариант через пункт «Создать «…»» | Теги, метки, категории |

**Только из списка.**
- Пока пользователь печатает, значение не меняется: введённый текст — это запрос, а не значение;
- Если поле потеряло фокус, а текст не совпал ни с одним вариантом, поле возвращает последнее выбранное значение (или пустое, если его не было). Ошибку при этом не показываем;
- Если текст полностью совпал с одним вариантом (без учёта регистра), этот вариант выбирается.

**Свободное значение.**
- Enter или уход фокуса сохраняет введённый текст как значение;
- Список остаётся подсказкой, а не ограничением.

**Создание.**
- Пункт «Создать «{запрос}»» появляется, когда введённый текст не совпадает полностью ни с одним вариантом. Правила пункта — `dropdown.md`, «Создать …»;
- После создания новое значение выбирается, Dropdown закрывается;
- Если создание требует ответа системы, на время запроса в поле показывается Spinner.

## Фильтрация и подсветка совпадения
- По умолчанию вариант подходит, если его Label **содержит** запрос, а не только начинается с него;
- Регистр не учитывается, «е» и «ё» считаются одной буквой;
- Порядок: сначала варианты, которые начинаются с запроса, затем остальные совпадения. Внутри каждой группы сохраняется исходная сортировка;
- Совпавшая часть Label выделяется полужирным — `dropdown.md`, «Подсветка совпадения»;
- Group Title остаётся, если в группе есть хотя бы одно совпадение.

## Минимальная длина запроса
- Для списка, который уже есть на клиенте, фильтрация начинается с первого символа;
- Для асинхронного поиска запрос отправляется от 2 символов;
- Пока символов меньше минимума, Dropdown показывает подсказку «Введите не меньше 2 символов» (или ничего, если список до ввода не нужен).

## Асинхронный поиск
Последовательность:
1. Пользователь вводит запрос;
2. После паузы в вводе (debounce) отправляется запрос; в Dropdown появляется Loading (`dropdown.md`, «Loading»);
3. Ответ заменяет Loading списком, Empty или пунктом «Создать «…»».

Правила:
- Не отправляйте запрос на каждый символ без debounce;
- Показывайте только ответ на последний запрос. Ответы на устаревшие запросы отбрасываются;
- Старые результаты не выдаются за актуальные: пока идёт новый запрос, их нет;
- Ошибка загрузки показывается внутри Dropdown с действием «Повторить», поле при этом не получает Error;
- Spinner в поле — это проверка выбранного значения, а не загрузка списка (`select.md`, «Асинхронная проверка»).

## «Ничего не найдено»
- Если запрос не дал результатов, Dropdown остаётся открытым и показывает «Ничего не найдено»;
- Если разрешено создание, вместо сообщения показывается пункт «Создать «{запрос}»»;
- Если разрешено свободное значение, можно показать подсказку «Нажмите Enter, чтобы сохранить «{запрос}»»;
- Результат объявляется screen reader через live region: «Найдено: N» или «Ничего не найдено».

## Clear
- Показывается, когда в поле есть текст или выбранное значение;
- Очищает и текст запроса, и выбранное значение;
- После очистки фокус остаётся в поле, Dropdown не открывается сам;
- Не показывается в Disabled и Read Only.

## Открытие и закрытие
| **Событие** | **Dropdown** |
|:--|:--|
| Фокус на поле | Не открывается |
| Ввод символа | Открывается с отфильтрованным списком |
| Клик по Chevron | Открывает / закрывает; фокус остаётся в поле |
| ↓, Alt + ↓ | Открывает |
| Выбор варианта | Закрывается, в поле — Label выбранного варианта |
| Escape, Tab, клик вне | Закрывается |

## Управление клавиатурой
Фокус всегда остаётся в поле ввода. Active Item передаётся через `aria-activedescendant`.
| **Действие** | **Результат** |
|:--|:--|
| Tab | Переводит фокус в поле и далее на следующий контрол. Открытый Dropdown закрывается без выбора |
| Печать символов | Вводит текст и фильтрует список |
| ↓ | Открывает Dropdown; в открытом — переводит Active на следующий вариант |
| ↑ | В открытом Dropdown переводит Active на предыдущий вариант |
| Alt + ↓ | Открывает Dropdown без перемещения Active |
| Alt + ↑ | Закрывает Dropdown без выбора, введённый текст остаётся |
| Enter | Выбирает Active Item и закрывает Dropdown. Если Active нет и разрешено свободное значение — сохраняет введённый текст |
| Escape | Открытый Dropdown — закрывает без изменения значения. Закрытый — очищает поле |
| ← / →, Home / End | Перемещают каретку в тексте, Active не меняется |
| Backspace / Delete | Удаляют текст, список фильтруется заново |

💡
Chevron — кнопка без отдельной Tab-остановки (`tabindex="-1"`): всё, что она делает, доступно с клавиатуры из поля.

## Regular и Inverse
| **Режим** | **Где применять** |
|:--|:--|
| Regular | Светлые и стандартные поверхности |
| Inverse | Темные поверхности |

Inverse — режим dark на фрейме; Dropdown повторяет режим поля.

## Доступность (A11y)
- Поле ввода — `role="combobox"` с `aria-expanded`, `aria-controls` на Dropdown и `aria-autocomplete` по режиму;
- Dropdown — `role="listbox"`, варианты — `role="option"` с `aria-selected`;
- Active передаётся через `aria-activedescendant`, DOM-фокус остаётся в поле;
- Имя поля — Label из Field, связанный программно; Placeholder не заменяет Label;
- Число результатов, Empty и Loading объявляются через live region, без переноса фокуса;
- Chevron — `aria-hidden` или кнопка с доступным именем «Показать варианты» и `tabindex="-1"`;
- Clear — кнопка с доступным именем «Очистить»;
- Error — `aria-invalid="true"` и связанное текстовое сообщение;
- Выбор варианта не меняет контекст страницы: переход, отправка формы и перезагрузка — только по отдельному действию (WCAG 2.2, 3.2.2 On Input);
- Focus Ring виден при клавиатурной навигации.

## Адаптив
- На узком экране поле занимает доступную ширину;
- Dropdown не перекрывается экранной клавиатурой: если места не хватает, список открывается вверх или поле прокручивается к верху экрана;
- Не уменьшайте текст и активные области ради desktop-ширины.

## Делать
- Использовать Combobox для длинных списков и справочников;
- По умолчанию разрешать только значения из списка;
- Выделять совпадение начертанием;
- Сообщать о результатах поиска текстом.

## Не делать
- Не открывать список по одному только фокусу;
- Не показывать устаревшие результаты асинхронного поиска;
- Не очищать введённый текст при закрытии списка по Tab;
- Не использовать Combobox для множественного выбора.

## Связанные компоненты
| **Компонент** | **Когда использовать** |
|:--|:--|
| Field | Label, Description, Required и Validation Message |
| Select | Известный список без поиска |
| Multiselect | Несколько значений, в том числе с поиском |
| Input | Произвольный текст без списка |
| Search Input | Поиск по контенту |
| Dropdown / Dropdown Item | Список вариантов (`dropdown.md`) |

# Решения для согласования
1. **Режим по умолчанию — List** (`aria-autocomplete="list"`), без автоматического Active на первом варианте. Выбор требует ↓ или клика, так случайный Enter не подставит чужое значение. APG описывает оба варианта: с ручным и с автоматическим выбором.
2. **Только из списка — по умолчанию.** Непринятый текст при потере фокуса откатывается к последнему значению без Error. Альтернатива — оставлять текст и показывать Error «Выберите вариант из списка». Она нагляднее, но создаёт ошибку там, где пользователь просто ушёл из поля.
3. **Фильтр «содержит», совпадения с начала — выше**, регистр не учитывается, «е» = «ё».
4. **Минимальная длина запроса: 1 символ локально, 2 — для асинхронного поиска.** Число 2 — наше предложение: оно отсекает запросы по одной букве, которые возвращают почти весь справочник.
5. **Debounce для асинхронного поиска — 300 мс.** Наше предложение, нужно подтверждение фронтенда. Внешних норм нет.
6. **Список не открывается по фокусу.** APG это допускает, но при Tab-навигации по форме список, открывающийся на каждом поле, мешает.
7. **Escape на закрытом списке очищает поле** — опциональное поведение APG. Пользователь попросил его явно.
8. **Chevron без Tab-остановки** (как в примерах APG).
9. **Ошибка загрузки — внутри Dropdown**, поле не получает Error: ошибка относится к списку, а не к значению.
10. **«Ничего не найдено» и «Создать …» не показываются вместе** — следует правилу `dropdown.md` «не показывать одновременно Empty и Dropdown Item».
