# Философия форм

## 1. Назначение документа

Этот документ описывает единый закон формы для всех компонентов дизайн-системы. Когда элемент скруглённый, когда угловатый и почему. Регламент задаёт принцип, границы его применения, исключения и анти-паттерны.


> Цель вести диалог с пользователем через форму компонента, что является осознанным решением, а не случайностью, но при этом не вредила UX там, где семантика формы конфликтует с базовыми ожиданиями пользователя.


## 2. Базовый закон


> Circle = человек (персона).
>
> Square = система (объект).


Это перцептивный закон. Он работает на уровне восприятия, когда круглое читается как «живое и человеческое», угловатое как «системное и техническое».


## 3. Три слоя интерфейса

Форма решается по-разному в зависимости от того, к какому слою принадлежит компонент. Это ключ к тому, чтобы регламент не ломался на практике.



| **Слой** | **Что это** | **Вопрос** | **Как решается форма** |
|----|----|----|----|
| Сущности | avatar, chip, badge | «что это» | по оси природы (человек — система) |
| Управление | button, input, tabs, toggle, status | «что делает, куда ведёт» | по правилам своего компонента, ось природы не применяется к ним |
| Сигналы | dot, spinner, presence-индикатор | «есть внимание, процесс жив» | почти всегда круг |


**Главный принцип разделения:**


:::info
Ось «человек — система» применяется только к слою сущностей. Управление и сигналы живут по своим правилам.

:::


## 4. Две независимые оси **· только сущности**

Форма и содержимое сущности решаются раздельно и не влияют друг на друга.


Ось А — это форма (это про внешний контур).

**Вопрос задаем: человек или объект (система)?**

* Человек — круг
* Объект / система — квадрат


Ось Б — наполнение (смотрим что внутри сущности на примере Аватара).

**Вопрос задаем: насколько сильный визуальный бренд?**

* Сильный бренд = логотип
* Стандартный тип =  type-иконка
* Есть короткое имя = инициалы
* Есть фото = фото


:::info
Наполнение никогда не влияет на форму контура. Логотип не делает элемент круглым, инициалы не делают квадратным.

:::


## 5. Формулы


1. Круглый chip, avatar, badge = «гибкая, человеческая» сущность (теги, люди, произвольные значения);
2. Квадратный chip, avatar, badge = «структурная, системная» сущность (статусы, типы, объекты, версии);
3. Status = всегда квадрат (независимо от носителя);
4. Управление = единый radius-токен продукта (не зависит от природы) потому что это компоненты иной категории;
5. Сигнал без содержимого = круг (точка, спиннер).


## 6. Дерево принятия решения

Для любого компонента прогоняем сверху вниз

1\. Это сигнал? Точка, спиннер, индикатор присутствия? — да? — круг.

2\. Это управление? Действие, навигация, ввод? — да? — форма по правилам компонента, ось природы не применяется. 

3\. Если это не управление, значит это 

3\.1. Статус? — квадрат.

3\.2. Элемент входит в однородную группу (ряд фильтров, токены)? — да — форма для всей группы (см. раздел 9). 

3\.3. Природа сущности человек? — круг. Объект (система)— квадрат 

3\.4. Наполнение решаем отдельно (ось Б).


## 7. Применение по компонентам

### 7.1. Avatar

Форма определяется по природе носителя.

| **Сущность** | **Форма** | **Наполнение** |
|----|----|----|
| Пользовател, автор, участник | Круг | фото, инициалы |
| Компания | Квадрат | логотип, инициалы (реже иконка) |
| Проект | Квадрат | инициалы, иконка |
| Команда | Квадрат | инициалы, иконка |
| Интеграция | Квадрат | логотип сервиса, иконка |
| Файл | Квадрат | type-иконка |
| Бот | Квадрат | робот-иконка, (реже кастомный аватар) |


### 7.2. Chip

Форма определяется по природе значения.

| **Тип chip** | **Форма** |
|----|----|
| Тег, ключевое слово, категория | Круг |
| People-chip (упоминание, ассайни, участник) | Круг |
| Chip произвольного значения | Круг |
| Тип, вид объекта | Квадрат |
| Техническое значение (версия, ID, код) | Квадрат |
| Object-chip (проект, команда, интеграция, бот) | Квадрат |


:::info
Данное правило действует для одиночных (разнесённых по контексту) chip. Внутри однородной группы смотри в Раздел 9.

:::


### 7.3. Badge

| **Тип badge** | **Слой** | **Форма** |
|----|----|----|
| Тип, флаг (new, beta, pro) | сущность | Квадрат |
| Dot / индикатор непрочитанного (12, 99+) | сигнал | Круг |
| Presence-точка на аватаре | сигнал | Круг |


### 7.4. Tabs

Табы — слой управления (навигация). Ось природы не применяется. Форма по характеру навигации.

| **Тип табов** | **Форма** | **Когда** |
|----|----|----|
| Underline, squared tabs | Квадрат,  подчёркивание | навигация по разделам системы и типам (Overview, Settings, API, Logs) |
| Segmented, pill tabs | Скруглённые | переключение мягких пользовательских представлений (Все, Мои, Избранное) |


### 7.5. Прочие компоненты

Управление (форма по radius-токену продукта, не по природе)

| **Компонент** | **Форма** | **Логика** |
|----|----|----|
| Button | единый radius-токен | кнопка как глагол, и радиус = характер продукта, а не семантика |
| Input / Select / Textarea | единый radius (ближе к квадрату) | поле структурно |
| Dropdown / Menu item | Квадрат | структурный список действий |
| Modal / Sheet / Popover | radius-токен контейнера | форма не варьируется по содержимому |
| Toggle / Switch | Всегда pill | имитация физического тумблера, human-facing |


**Сигналы (круг по умолчанию):**

| **Компонент** | **Форма** |
|----|----|
| Spinner (индетерминантный) | Круг |
| Notification dot, presence | Круг |
| Progress bar (детерминантный) | Линейный / квадратный |


**Selection (платформенная конвенция, подтверждает закон):**

| **Компонент** | **Форма** | **Логика** |
|----|----|----|
| Radio | Круг | один мягкий взаимоисключающий выбор |
| Checkbox | Квадрат | дискретное структурное состояние |

## 8. Исключения **·** жёсткие правила

Эти правила имеют приоритет над осью природы:


1. Статус всегда квадрат. Независимо от носителя (chip, badge, аватар со статусом).
2. Число / техническое значение — квадрат. Счётчик, версия, ID, код.
3. Управление не подчиняется оси природы. У кнопок, полей, меню, единый radius-токен продукта.
4. Toggle — всегда pill. Физическая метафора важнее классификации.
5. Сигнал без содержимого — круг. Точка, спиннер, presence.


\
## 9. Границы применения **·** критический раздел

Философия форм работает как семантический сигнал только при выполнении двух условий:


1. Элемент выступает самостоятельно или разнесён по контексту.
2. Контекст не сравнительный (элементы не стоят вплотную в однородном ряду).


:::info
Внутри одной функциональной группы (ряд активных фильтров, панель chip) форма единая. Консистентность здесь важнее семантики формы.\n

**Пример**

* Круглые фильтры-люди + квадратные фильтры-статусы вперемешку — это неправильно.
* Все фильтры одной формы, тип различается иконкой и текстом — это праивльно.


:::

* В однородном ряду пользователь читает разную форму как разное поведение / разный тип контрола, а не как семантику. Это ложный сигнал.
* Форма в иерархии восприятия сильнее семантики, разная форма = ожидание разного действия.
* Философия форм не выучена пользователем, для него разноформенность в ряду выглядит как необъяснённая непоследовательность, а не как система.
* Смешанные круглые, квадратные края в ряду создают визуальный шум и неровность.


## 10. Анти-паттерны

*  Разные формы chip/фильтров в одном однородном ряду.
*  Круглый chip для статуса (ломает жёсткое исключение).
*  Круглый счётчик-badge «для красоты» (число системно → квадрат).
*  Разный radius у кнопок в зависимости от важности (управление → единый токен).
*  Квадратный аватар человека ради выравнивания по сетке (форма = природа, а не layout).
*  Применение оси «человек/система» к навигационным табам-разделам.
*  Влияние наполнения (логотип/иконка) на форму контура.


\
## 11. Область применения и ограничения принципа

Оценка зрелости правила

| **Уровень применения** | **Устойчивость** | **Рекомендация** |
|----|----|----|
| Avatar | Высокая | Применять |
| Одиночные статусы, badge | Высокая | Применять |
| Изолированные, разнесённые chip | Средняя | Применять с осторожностью |
| Chip внутри однородных групп | Низкая | не применять ось природы — единая форма |


**Риски при масштабировании:**

* Рост пограничных случаев («регион — это тип или значение?») требует ручного судейства = замедление и споры.
* Протаскивание «природы данных» в UI-слой = техдолг.
* Фильтры часто генерируются из данных, где природа неизвестна — форма может «поехать».



:::tip
Философия форм здесь будет ценна как высокоуровневый принцип-компас и элемент айдентики. Она не должна становиться жёстким законом на уровне каждого (к примеру) chip внутри групп — там приоритет у консистентности и UX-ожиданий.

:::

## 12. Итоговая сводная таблица

| **Слой** | **Круг** | **Квадрат** |
|----|----|----|
| Сущности | человек, персона, автор, участник | объект, проект, команда, интеграция, файл, бот |
| Сущности-состояния | — | статус, тип, версия, счётчик |
| Навигация | segmented (мягкие view-режимы) | underline/squared (разделы системы) |
| Управление | toggle | button / input / menu (по radius-токену) |
| Сигналы | dot, spinner, presence | progress bar |
| Selection | radio | checkbox |


\
## 13. Резюме в трёх тезисах


1. Форма несёт смысл по оси «человек (круг) — система (квадрат)» — но только для слоя сущностей и только вне однородных групп.
2. Статус, числа и технические значения — всегда квадрат. Управление — по единому radius-токену. Сигналы — круг.
3. Внутри однородной группы консистентность важнее семантики = единая форма, а тип кодируем иконкой и текстом, а не контуром.



:::tip
Регламент фиксирует принцип, его границы и исключения. При появлении новых компонентов надо прогонять через дерево решений (Раздел 6) и проверять по правилу однородной группы (Раздел 9).

:::
