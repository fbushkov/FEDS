# Radiobutton&RadiobuttonCard

# Radiobutton

**Radiobutton** — интерактивный элемент одиночного выбора. Он позволяет выбрать только один вариант из предложенных.

**Главное отличие от Checkbox**: Checkbox допускает выбор нескольких вариантов или отсутствие выбора. Если из группы можно выбрать только один вариант, используйте Radio.

**Главное отличие от Toggle**: Radiobutton обычно фиксирует выбор внутри формы и применяется после подтверждения. Toggle изменяет настройку сразу.

## **Использовать**

* Одиночный выбор из списка независимых вариантов;
* Выбор элемента в таблице, списке.

## **Не использовать**

* Если разрешен выбор нескольких вариантов — используйте Checkbox;
* Если изменение применяется мгновенно, как настройка on/off — используйте Toggle;
* Если нужен компактный интерактивный фильтр или удаляемое значение — используйте Chip;
* Не смешивайте обычные Radiobutton и Radiobutton Card в одной группе: карточки будут выглядеть более приоритетными.

## Логическое состояние

Логическое состояние не следует смешивать с интерактивными состояниями Hover, Pressed или Focused.

| **Состояние** | **Описание** | **Когда применять** |
|----|----|----|
| No Active | Вариант не выбран | Базовое состояние |
| Active | Вариант выбран | Пользователь выбрал опцию |

## **Размеры**

| **Размер** | **Где применять** |
|----|----|
| M | Стандартный размер: формы, таблицы, фильтры, плотные списки |
| L | Интерфейсы с более крупной типографикой, длинными подписями и увеличенной активной областью |

* Все Radiobutton в одной группе должны быть одного размера;
* Не уменьшайте активную область до визуального квадрата Radiobutton: в нее должна входить подпись;
* Для touch-интерфейсов используйте L или обеспечьте достаточные отступы вокруг M.

## **Направление**

| **Вариант** | **Описание** | **Когда применять** |
|----|----|----|
| Left | Radiobutton расположен слева от контента | Стандартный вариант для форм, списков и фильтров |
| Right | Radiobutton расположен справа от контента | Строки и списки, где элементы управления выровнены по правому краю |

* В одной группе используйте только одно направление;
* Left — вариант по умолчанию.

## **Конфигурация**

| **Конфигурация** | **Состав** | **Применение** |
|----|----|----|
| Text | Radiobutton + название | Базовый вариант |
| Description | Radiobutton + название + пояснение | Когда нужно уточнить последствия или содержание выбора |
| Avatar | Radiobutton + аватар + название, опционально описание | Выбор пользователя, исполнителя, команды или сущности |
| Без видимого текста | Только Radiobutton | Только в плотных таблицах, когда контекст однозначно задан строкой или колонкой |

## **Название и описание**

* Название формулируйте как понятное утверждение или самостоятельный вариант;
* Используйте позитивные формулировки: «Получать уведомления», а не «Не отключать уведомления»;
* Подпись должна однозначно объяснять оба результата: что произойдет при Active и при No Active;
* Description дополняет название, но не заменяет его;
* Не помещайте в Description критически важное условие, которое пользователь может пропустить.

## Перенос и сокращение текста

По умолчанию длинное название и Description переносятся на следующую строку.

В плотных интерфейсах допустимо сокращение:

* Название — одна строка с многоточием;
* Description — одна или несколько строк по правилам продукта;
* Полный текст показывается в Tooltip;
* Tooltip не должен быть единственным способом узнать обязательное условие.

## **Состояния**

| **Состояние** | **Когда применяется** | **Поведение** |
|----|----|----|
| Default | Компонент готов к взаимодействию | Может быть No Active, Active |
| Hover | Курсор находится над активной областью | Подсвечивается интерактивная область |
| Pressed | Момент нажатия | Отображается состояние нажатия |
| Focused | Навигация с клавиатуры | Видимый Focus Ring |
| Disabled | Выбор недоступен | Состояние нельзя изменить |
| Loading | Контент или значение еще загружается | Показывается Skeleton, взаимодействие недоступно |
| Error | Обязательно нужно выбрать один из вариантов | Ошибка обозначается визуально и текстом |

#### Активная область

Для обычного Radiobutton активной является общая область **Radiobutton + Text**. Если в конкретном интерфейсе требуется дополнительная фоновая подсветка Hover или Pressed, она задается в макете на уровне контейнера строки.

#### Disabled

* Сохраняйте видимым текущее логическое состояние;
* По возможности объясняйте причину недоступности рядом с компонентом.

#### Loading

* Используйте, если значение или подпись загружаются асинхронно.
* Не показывайте активный Radiobutton до получения данных.

#### Error

Error применяется опционально, когда ни один из вариантов не выбран по дефолту, но выбор обязателен для продолжения сценария.

* Не окрашивайте Radiobutton в Error только потому, что он не выбран;
* Показывайте Error после валидации.

## Группа Radiobutton

* Размещайте варианты вертикально, если горизонтальная компоновка затрудняет связь подписи с Radiobutton;
* Добавляйте общий заголовок-вопрос;
* Опции располагайте в логичном порядке: по частоте, этапу процесса или приоритету;
* Не смешивайте размеры, направления и визуальные варианты внутри группы;

## **Делать**

* Делайте кликабельными Radiobutton и связанную с ним подпись;
* Сохраняйте единые размер, направление и конфигурацию в группе;
* Используйте перенос для длинного текста.

## **Не делать**

* Не формулируйте подписи через двойное отрицание;
* Не делайте кликабельным только маленький квадрат;
* Не размещайте вложенные интерактивные элементы внутри активной Radiobutton Card;
* Не смешивайте обычные Radiobutton и Radiobutton Card в одной группе.

## **Доступность (A11y)**

* Предпочтительно использовать нативный <input type="checkbox"> со связанным <label>;
* Radiobutton должен получать фокус по Tab и переключаться клавишей Space;
* Клик по Label должен переключать Radiobutton и увеличивать активную область;
* Для кастомной реализации используйте role="checkbox" и aria-checked="false", "true" или "mixed";
* Для группы связанных Radiobutton используйте <fieldset> и <legend>;
* Description и сообщение об ошибке связывайте через aria-describedby;
* Required передавайте программно и поясняйте пользователю до отправки формы;
* Минимальная активная область — 24 × 24 CSS px; для touch-сценариев желательно стремиться к 44 × 44 CSS px;
* Radiobutton Card должна быть одной интерактивной сущностью, а не отдельными focusable-карточкой и Radiobutton.

## **Адаптив**

* На mobile увеличивайте активную область, не уменьшая ее до визуального Radiobutton;
* Длинные подписи переносятся, Radiobutton остается выровнен по первой строке;
* Radiobutton Card на экране телефона занимает всю доступную ширину;
* Многоколоночная сетка карточек перестраивается в одну колонку;
* Не используйте горизонтальный скролл для обязательных вариантов формы;
* Сохраняйте видимый Focus для устройств с подключенной клавиатурой.

## **Связанные компоненты**

| **Компонент** | **Когда использовать вместо Radiobutton** |
|----|----|
| Checkbox / Checkbox Card | Можно выбрать несколько вариантов |
| Toggle | Настройка применяется сразу после переключения |
| Chip | Компактный фильтр, тег или интерактивное выбранное значение |
| Select / Multiselect | Вариантов много или требуется поиск |


# Radiobutton Card

Radiobutton Card — расширенный вариант Radiobutton с контейнером. Он используется, когда требуется сделать выбор заметнее, а для принятия решения пользователю недостаточно короткой подписи и нужно показать подробное описание и дополнительную информацию.

## **Использовать**

* Выбор Radiobutton Card является главным действием на экране;
* Вариантам требуется пояснение, чтобы пользователь мог их сравнить;
* Нужно показать дополнительную иконку;
* Требуется крупная активная область для desktop и touch.

## **Не использовать**

* Для простого списка коротких названий — используйте обычный Radiobutton;
* Для длинного списка — используйте Select или Multiselect;
* Не используйте карточки разных размеров или направлений в одной группе.

## **Размеры**

| **Размер** | **Где применять** |
|----|----|
| M | Стандартные карточки с коротким названием и опциональным Description |
| L | Карточки с аватаром, более длинным описанием или увеличенной активной областью |

## **Направление и иконка**

| **Вариант** | **Структура** | **Применение** |
|----|----|----|
| Left | Radiobutton → контент | Стандартная карточка выбора |
| Right | Контент → Radiobutton | Контент является первым объектом сканирования, контроль выровнен справа |
| Right + Icon | Иконка → контент → Radiobutton | Только для варианта с Radiobutton справа |

* Дополнительная иконка используется только при направлении Right;
* В одной группе сохраняйте одинаковое направление и одинаковую структуру карточек.

## **Конфигурация**

| **Конфигурация** | **Состав** | **Применение** |
|----|----|----|
| Text | Название | Минимальный вариант карточки |
| Description | Название + пояснение | Сравнение условий, характеристик или последствий выбора |
| Avatar | Аватар + название, опционально Description | Выбор пользователя, команды или связанной сущности |
| Icon | Иконка + название, опционально Description | Категории и варианты, которые легче различить визуально |

## **Состояния**

Radiobutton Card наследует логические состояния Radiobutton: No Active и Active.

| **Состояние** | **Активная область и отображение** |
|----|----|
| Default | Вся карточка доступна для выбора |
| Hover | Активна и подсвечивается область всего контейнера |
| Pressed | Состояние нажатия отображается на всем контейнере |
| Focused | Видимый Focus Ring у интерактивного Radiobutton; карточка не создает дополнительную Tab-остановку |
| Disabled | Весь контейнер и его контент недоступны |
| Loading | Сохраняется контейнер карточки, внутри отображается Skeleton |
| Error | Ошибка обозначается у карточки и сопровождается текстовым сообщением |

#### Активная область

* Клик в любой точке контейнера должен переключать Radiobutton;
* Внутри должна быть одна focusable-точка — сам Radiobutton;
* Контейнер не должен получать отдельный tabindex;
* Курсор, Hover и Pressed должны подтверждать кликабельность всего контейнера.

#### Сетка

* На широком экране карточки можно размещать в несколько колонок;
* На узком экране перестраивайте их в одну колонку;
* Вся сетка использует один размер и направление.
