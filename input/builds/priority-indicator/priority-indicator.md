# Priority Indicator

Индикатор приоритета — неинтерактивный информационный компонент, отображающий приоритет задачи с помощью иконки и текста. Используется, например, в таблицах задач (столбец «Приоритет»), на странице задачи и в выпадающем списке выбора приоритета. Компонент представляет собой семантическую метку (значок + подпись): он прост для восприятия и особенно эффективен в контекстах плотных списков задач.

## **Использовать**

* Приоритет задачи в интерфейсах (таблицы, деталка задачи, селект выбора);
* Требуется быстро донести значение приоритета (с помощью иконки и цвета);

## **Не использовать**

* Не применять индикатор приоритета там, где нужен интерактивный выбор или фильтрация. Для выбора приоритета используйте выпадающий список (Select), а для фильтрации/тегов — соответствующие интерактивные компоненты (Tag/Chip).
* Если нужна возможность удаления или изменения приоритета «на лету», не делайте это через статичный индикатор.
* Не полагайтесь только на цвет приоритета: цвет всегда дублируйте иконкой или текстом.

## Варианты

| **Режим** | **Описание** |
|----|----|
| **Полный (иконка + текст)** | Иконка слева + текст. Стандартный режим для системных и кастомных приоритетов (таблицы, селекты, деталки). |
| **Только иконка** | Только значок без текста. Допустим **только для системных приоритетов** в очень плотных интерфейсах (компактный режим, например, в меню списка). Для понимания обязательно добавлять tooltip или aria-label с пояснением значения. |

## Системные приоритеты

* Системные приоритеты — это закрытый набор значений («Не задан», «Незначительный», «Низкий», «Средний», «Высокий», «Критический», «Блокер»), семантика которых известна заранее\*
* Для каждого из них в дизайн-токенах заранее заданы иконка и цвет;
* Иконки в этом случае сами несут смысл (направление стрелок или символ стопа), поэтому для них возможен режим «только иконка» с подсказкой.

## Кастомные приоритеты

* Кастомные приоритеты задает пользователь (например, буквы A, B, C с описанием).
* Семантика не универсальна и известна только в контексте конкретного проекта.
* «Иконка» кастомного приоритета — это просто буквенный код (A, B и т. д.) в бейджике, а полный смысл передает текст (например, «A — влияет на деньги»).
* Нельзя отображать кастомный приоритет только иконкой (буквой) — без текста значение не очевидно.
* Цвет кастомных приоритетов несемантичный, а выбирается из вариантов компонента «Badge».

## Цвет

| **Режим** | **Описание** |
|----|----|
| Серый | Не задан |
| Светло-зеленый | Незначительный |
| Зеленый | Низкий |
| Желтый | Средний |
| Светло-красный | Высокий |
| Красный | Критический |
| Тесно-красный | Блокер |

## Размеры

* **M** — стандартный размер для большинства интерфейсов (таблицы, формы, детальная информация).
* **S** — компактный размер для плотных интерфейсов (мобильная версия таблицы, плотный список приоритетов).


:::warning
В одном интерфейсе все индикаторы приоритета одного контекста должны быть одного размера (не смешивать M и S).

:::

## **Доступность (A11y)**

* **Дублирование цвета.** Не стоит полагаться только на цвет: все смысловые цвета дублируйте текстом или значками;
* **Иконки и подписи.** В режиме *«только иконка»* обязательно обеспечить альтернативный текст (tooltip/aria-label) с расшифровкой приоритета;
* **Фокусировка.** Индикатор приоритета сам по себе не интерактивен и обычно не доступен через Tab. Если он находится внутри интерактивного элемента (например, выпадающего списка), то фокус управляется контейнером.

## **Состояния**

* **Default.** Основное состояние статического индикатора.
* **Loading.** Если приоритет загружается, можно показывать скелетон;
* **Hover/Pressed.** Отдельных состояний у самого индикатора нет, так как он не реагирует на действия (внешние состояния обрабатывает содержащий элемент).

## Делать

Цвет, иконка и текст должны соответствовать семантике приоритета. Для плотных списков системных приоритетов допускается режим только-иконка с тултипом. Обязательно используйте текстовую подпись для кастомных приоритетов.

## Не делать

Нельзя показывать кастомный приоритет без текста (только букву). Не полагайтесь на цвет как единственный признак. Не смешивайте разные режимы и размеры в одном списке (все индикаторы одного контекста — одного формата и размера).
