# Input   
Input — однострочное поле для ввода и редактирования короткого текстового или числового значения с клавиатуры.   
Компонент отвечает только за само поле: значение, placeholder, Leading Zone, Trailing Zone и визуальные состояния. Label, Description, сообщение валидации и счетчик относятся к обертке поля — Field.   
## Использовать   
- Для короткого текстового или числового значения;   
- Когда пользователю нужно ввести или отредактировать значение вручную;   
- Для значения без сложного заранее заданного формата.   
   
## Не использовать   
|                                                                                                                          **Задача** |                              **Компонент** |
|:------------------------------------------------------------------------------------------------------------------------------------|:-------------------------------------------|
|                                                                                            Ввести длинный текст или несколько строк |                                   Textarea |
|                                                             Ввести телефон, дату, время, валюту или другое форматированное значение |                   Специализированный Input |
|                                                                                       Выбрать значение из заранее известного списка |                          Select / Combobox |
|                                                                                                            Найти объект или контент |                               Search Input |

💡   
Если формат значения важен для корректного ввода, используйте специализированный компонент или маску, а не объясняйте формат только через Placeholder.   
   
## Конфигурация   
|      **Зона** |                                          **Содержимое** |                                                        **Назначение** |
|:--------------|:--------------------------------------------------------|:----------------------------------------------------------------------|
|  Leading Zone |                          Icon, Prefix или Icon + Prefix |                                     Контекст перед вводимым значением |
|       Content |                                   Placeholder или Value |                                              Основное содержимое поля |
| Trailing Zone | Suffix, Clear, Action-1, Action-2, State Icon / Spinner |                                  Дополнительная информация и действия |

💡   
Не заполняйте все зоны без необходимости. Чем больше элементов внутри поля, тем меньше места остается для значения.   
   
## Размеры   
Компонент поддерживает три размера.   
|       **Размер** |                                                                                                                                                  **Где применять** |
|:-----------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|                S |                                                                                                                Таблицы, фильтры, плотные формы и компактные панели |
|                M |                                                                                                                            Стандартный размер для большинства форм |
|                L |                                                                            Основные поля на странице, крупные формы и сценарии с повышенным визуальным приоритетом |

- В одной группе полей используйте одинаковый размер;   
- Не уменьшайте внутренние отступы вручную ради размещения большего количества элементов.   
   
## Содержимое   
**Значение (Value)** — введенное или предзаполненное значение;   
**Placeholder** — дополнительная подсказка, которая видна только в пустом поле.   
**Правила Placeholder:**   
- Используйте, если по Label неочевидно, что или как вводить;   
- Не заменяйте Placeholder’ом Label;   
- Не дублируйте в нем название поля;   
- Не помещайте туда критичные требования, которые исчезнут после начала ввода;   
- Если нужно показать конкретное значение по умолчанию — предзаполните поле;   
- Для обязательного формата используйте маску или специализированный Input.   
- Используйте существительное с заглавной буквы.   
- Не добавляйте: «Введите», «Ваш» и двоеточие. Эти правила относятся к Label в Field Wrapper, а не к Placeholder.   
   
### Длинное значение   
- Input остается однострочным, текст не переносится на новую строку;   
- При вводе каретка должна оставаться видимой, содержимое сдвигается;   
- Leading и Trailing Zone остаются на месте;   
- Если пользователю важно видеть длинное значение целиком, используйте достаточную ширину поля или Textarea.   
   
## Leading Zone   
Leading Zone располагается перед Value.   
|        **Вариант** |                                                                                                                **Когда применять** |
|:-------------------|:-----------------------------------------------------------------------------------------------------------------------------------|
|               Icon |                                                           Помогает распознать назначение поля: поиск, ссылка, пользователь и т. п. |
|             Prefix |                                                                                 Неизменяемая часть значения: протокол, символ, код |
|      Icon + Prefix |                                                                             Когда нужны оба элемента и каждый несет полезный смысл |

### Prefix   
Prefix является частью контекста значения, но пользователь его не редактирует.   
Примеры: `https://` , `@` , код или фиксированная часть идентификатора.   
💡   
Не используйте Prefix как замену Label.   
### Icon   
Leading Icon по умолчанию не является кнопкой. Если иконка запускает действие, это уже Action и ее следует размещать как интерактивный элемент с соответствующей семантикой.   
## Trailing Zone   
Trailing Zone располагается после Value.   
|        **Элемент** |                                                                       **Назначение** |                **Интерактивность** |
|:-------------------|:-------------------------------------------------------------------------------------|:-----------------------------------|
|             Suffix |                                         Единица измерения или неизменяемое пояснение |                                Нет |
|              Clear |                                                          Очистить введенное значение |                                 Да |
|           Action-1 |                                         Контекстное действие над полем или значением |                                 Да |
|           Action-2 |                                                       Второе дополнительное действие |                                 Да |
|         State Icon |                                                            Error / Warning / Success |                                Нет |
|            Spinner |                                          Асинхронная проверка или загрузка состояния |                                Нет |

Рекомендуемый порядок слева направо:   
**Suffix → Clear → Action-1 → Action-2 → State Icon / Spinner**   
State Icon и Spinner занимают системную крайнюю позицию и не считаются пользовательскими Action.   
### Suffix   
Suffix помогает интерпретировать значение: единица измерения, валюта или короткое фиксированное обозначение.   
- Не используйте его для длинного пояснения;   
- Если Suffix критичен для понимания, он должен быть доступен для assistive technology.   
   
### Actions   
Допускается до двух дополнительных действий.   
Примеры:   
- Скопировать;   
- Показать / скрыть;   
- Открыть связанный объект;   
- Запустить специфичное для поля действие.   
   
Каждая Action:   
- Имеет одну понятную функцию;   
- Использует иконку с Tooltip;   
- Имеет доступное имя ( `aria-label`);   
- Не дублирует действие Clear.   
   
💡   
Если действий больше двух, вынесите их из Input или используйте Menu.   
### Действие Clear   
Clear ( `×`) используется только для быстрого удаления введенного значения.   
- По умолчанию Clear отсутствует;   
- Показывается только в Filled-состоянии;   
- Не показывается в Disabled и Read Only;   
- После очистки фокус остается в Input;   
- Для часто очищаемых полей, Clear нужно показывать постоянно при наличии значения;   
- В форме с большим количеством полей допустимо показывать Clear по Hover, чтобы снизить визуальный шум.   
   
Кликабельная область Clear масштабируется вместе с размером S / M / L и не должна ограничиваться размером самой иконки.   
   
## Empty и Filled   
|        **Вариант** |                                                                                                                    **Описание** |
|:-------------------|:--------------------------------------------------------------------------------------------------------------------------------|
|              Empty |                                                                                    Значения нет, может отображаться Placeholder |
|             Filled |                                                     В поле есть Value; доступны действия, зависящие от значения, например Clear |

## Состояния   
|          **Состояние** |                                                                               **Когда применяется** |                                                                         **Поведение** |
|:-----------------------|:----------------------------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------|
|                Default |                                                                         Поле доступно и не в фокусе |                                                                   Базовое отображение |
|                  Hover |                                                                          Курсор находится над полем |                                                   Подсветка интерактивной поверхности |
|                Focused |                                                        Пользователь вводит или редактирует значение |                                                                    Яркая обводка поля |
|               Disabled |                                                                            Поле временно недоступно |                                                         Нет редактирования и действий |
|              Read Only |                                                        Значение можно прочитать, но нельзя изменить |                                         Фокус и допустимые действия могут сохраняться |
|                  Error |                                               Значение некорректно или обязательно, но не заполнено |                                                          Error-оформление + сообщение |
|                Warning |                                                             Значение допустимо, но требует внимания |                                                        Warning-оформление + пояснение |
|                Success |                                                                          Значение успешно проверено |                                                  Success-оформление при необходимости |
|                Loading |                                                                           Идет асинхронная проверка |                                                               Spinner в Trailing Zone |

💡   
Состояние Pressed для Input не нужен: после клика поле переходит в Focused.   
   
### Disabled и Read Only   
Эти состояния не взаимозаменяемы.   
|                                                                             **Disabled** |                                                                                 **Read Only** |
|:-----------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------|
|                                                       Поле недоступно для взаимодействия |                                                      Значение доступно для чтения и выделения |
|                                                                Не получает обычный фокус |                                                                          Может получать фокус |
|                                                                       Действия отключены |                                          Допустимые действия, например Copy, могут оставаться |
|                                   В HTML значение disabled-поля не отправляется с формой |                                                       Readonly-значение отправляется с формой |

Используйте Read Only, когда значение остается частью пользовательского сценария, но редактирование запрещено. Disabled — когда контрол недоступен.   
   
## Валидация   
### Error   
Используйте Error, когда пользователь должен исправить значение.   
- Показывайте состояние после проверки, а не заранее;   
- Объясняйте проблему текстом рядом с полем;   
- Не используйте только красную границу или иконку;   
- Error Icon внутри поля опциональна: если используется, применяйте ее последовательно.   
   
Примеры сообщений: «Введите корректный email», «Поле обязательно», «Максимум 50 символов».   
### Warning   
Warning сообщает о потенциальной проблеме, но не обязательно блокирует продолжение.   
Примеры:   
- Необычное значение;   
- Значение скоро станет недействительным;   
- Действие возможно, но требует внимания.   
   
Не используйте Warning вместо Error, если данные невозможно принять.   
### Success   
Success подтверждает успешную проверку, когда это действительно полезно.   
Не показывайте Success у каждого корректно заполненного поля: большое количество зеленых состояний создает визуальный шум.   
## Асинхронная валидация   
Spinner используется, когда результат зависит от ответа системы: например, проверяется уникальность имени или существование значения.   
**Последовательность:**   
1. Пользователь изменяет значение;   
2. Начинается проверка — в системной позиции Trailing Zone появляется Spinner;   
3. После ответа Spinner заменяется на Error / Warning / Success или исчезает.   
   
**Правила:**   
- Не показывайте одновременно Spinner и итоговую State Icon;   
- Не блокируйте ввод без необходимости;   
- Не запускайте дорогостоящую проверку на каждый символ без debounce, если это не требуется сценарием;   
- Сообщайте о результате текстом, если пользователь должен что-то сделать.   
   
## Regular и Inverse   
Input имеет два цветовых режима:   
|      **Режим** |                                               **Где применять** |   |
|:---------------|:----------------------------------------------------------------|:--|
|        Regular |                               Светлые и стандартные поверхности |   |
|        Inverse |                                              Темные поверхности |   |
|                |                                                                 |   |
|                |                                                                 |   |

## Ширина и композиция   
- Ширина поля должна соответствовать ожидаемой длине значения;   
- Не растягивайте короткие значения на всю страницу без причины;   
- В одной форме используйте ограниченное количество стандартных ширин;   
- Несколько связанных полей выравнивайте по общей сетке;   
- При нехватке места сначала уберите необязательные элементы Trailing Zone, а не сокращайте область Value до непригодной ширины.   
- Для очень узких экранов допустим *width: 100%*, если это соответствует структуре формы.   
   
## Доступность (A11y)   
- Используйте нативный  для текстового поля;   
- У Input должно быть программно связанное имя через  или aria-labelledby;   
- Placeholder не заменяет Label;   
- Description и сообщение валидации связывайте через aria-describedby;   
- Для Error используйте aria-invalid="true";   
- Для полей с известным назначением используйте подходящий autocomplete;   
- Clear и Action-иконки реализуйте как кнопки с доступным именем;   
- После Clear возвращайте / сохраняйте фокус в Input;   
- Декоративные иконки скрывайте от screen reader;   
- Значимые Prefix / Suffix включайте в доступное описание, если без них значение можно неверно понять;   
- Для Read Only используйте нативный readonly, а не Disabled;   
- Цвет Error / Warning / Success не должен быть единственным носителем смысла.   
   
## Управление клавиатурой   
|          **Действие** |                                                                                                      **Результат** |
|:----------------------|:-------------------------------------------------------------------------------------------------------------------|
|           Tab / Enter |                                                               Переводит фокус на Input и далее на доступные Action |
|           Shift + Tab |                                                                                             Перемещает фокус назад |
|               Стрелки |                                                                                   Перемещают каретку внутри текста |
|            Home / End |                                                                                Перемещают каретку в начало / конец |
|    Backspace / Delete |                                                                                                      Удаляют текст |
| Ctrl/Cmd + A, C, V, X |                                                       Стандартные операции выделения, копирования и редактирования |

## Делать   
- Использовать Input для короткого однострочного значения;   
- Сохранять достаточно места для Value;   
- Использовать Prefix / Suffix только как фиксированный контекст;   
- Ограничивать Trailing Zone двумя пользовательскими Actions;   
- Различать Disabled и Read Only;   
- Объяснять Error / Warning текстом;   
- Использовать Spinner для асинхронной проверки.   
   
## Не делать   
- Не использовать Placeholder вместо Label;   
- Не использовать Input для длинного текста;   
- Не помещать в поле множество декоративных иконок;   
- Не показывать Clear в пустом или Read Only поле;   
- Не использовать только цвет для валидации.

# Оболочка поля (база семейства)   
*(добавлено docs-writer 19.09.2026)*

Оболочка поля — общая база всех полей ввода и выбора: контейнер с фоном и обводкой, Placeholder / Value, Leading Zone, Trailing Zone и набор состояний. Отдельным компонентом она не является. Input — эталон оболочки, остальные документы семейства пишут «наследует оболочку Input» и описывают только отличия.   
Оболочку наследуют: Input, Search Input, Password Input, Number Input, Text Area, Select Button, Combobox, Multiselect, Date Picker. Схема семейства — `docs/forms-architecture.md`.   

## Состав оболочки   
|              **Часть** |          **Слой в Figma** |                                      **Обязательна** |
|:-----------------------|:--------------------------|:-----------------------------------------------------|
|              Контейнер |               `Container` |                    Да: фон, обводка, скругление, фокус |
|                  Value |                   `Value` |                                 Да, в Filled-состоянии |
|            Placeholder |             `Placeholder` |                  Нет; только в Empty и только если нужен |
|           Leading Icon |            `Leading Icon` |                                                    Нет |
|         Prefix, Suffix |        `Prefix`, `Suffix` |                                                    Нет |
|                  Clear |                   `Clear` |                             Нет, по умолчанию выключен |
|     Action-1, Action-2 |    `Action-1`, `Action-2` |                                                    Нет |
|   State Icon / Spinner |   `State Icon`, `Spinner` |              Нет; по состоянию, одновременно не показываются |
|                Chevron |                 `Chevron` |               Только у контролов с Dropdown, стоит последним |

Порядок в Trailing Zone для всей семьи:   
**Suffix → Clear → Action-1 → Action-2 → State Icon / Spinner → Chevron**   
Clear и Actions — экземпляры Icon Button (в макете Type = Tertiary). Своих цветов в поле у них нет.   

## Размеры оболочки   
|       **Размер** |                       **Высота** |   **Кликабельная область Clear** |
|:-----------------|:---------------------------------|:---------------------------------|
|                S |                32 px (по макету) |                24 px (по макету) |
|                M |         по шкале высот контролов |                28 px (по макету) |
|                L |         по шкале высот контролов |                32 px (по макету) |

- Высота S и области Clear сняты со спецификации Input в Figma. Высоты M и L, отступы и зазоры задаёт уровень 2 (решения ds-architect в `docs/decisions.md`);   
- Кликабельная область кнопки внутри поля растёт вместе с размером поля и не равна размеру иконки. Нижняя граница — 24 × 24 px (WCAG 2.2, критерий 2.5.8);   
- У Text Area размер задаёт отступы и типографику, а высота считается от числа строк.   

## Состояния оболочки   
|    **Состояние** |                          **Контейнер** |                     **Clear и Actions** |                                                 **Уточнение по макету** |
|:-----------------|:---------------------------------------|:----------------------------------------|:------------------------------------------------------------------------|
|          Default |                   Базовые фон и обводка |                                Доступны |                                                                          |
|            Hover |                  Подсветка поверхности |                                Доступны |                                                                          |
|          Focused |                 Акцентная обводка поля |                                Доступны |       Клик и переход с клавиатуры выглядят одинаково |
|         Disabled |       Приглушённые фон, текст и иконки |                         Не показываются |             Видны Prefix и Suffix, кнопок в Trailing Zone нет |
|        Read Only |   Отличается и от Default, и от Disabled |     Clear скрыт, остальные Actions доступны |        «Все кнопки-иконки Action остаются доступными» |
|            Error |                          Обводка Error |                                Доступны |          При наведении на State Icon — Tooltip с текстом ошибки |
|          Warning |                        Обводка Warning |                                Доступны |                                                                          |
|          Success |                        Обводка Success |                                Доступны |                                                                          |
|          Loading |                            Не меняется |                                Доступны |                    Spinner на месте State Icon |

**Приоритет, если признаки совпадают:** Disabled → Read Only → Focused → Error / Warning / Success → Hover → Default. Loading не меняет контейнер: Spinner только занимает место State Icon.   
**Focused поверх Error.** По макету в Focused оформление валидации пропадает, поле показывает обводку фокуса. Текст сообщения в Field и `aria-invalid` сохраняются до повторной проверки (см. «Решения для согласования»).   
**Контролы с Dropdown** добавляют признак Open. Он существует вместе с Focused и не заменяет его (`select.md`).   

## Свойства в Figma (текущий макет)   
Input `S - Base`: Filled, State, Inverse, Placeholder, Leading, Trailing, Suffix, Action-1, Action-2, Loading. Внутри Leading — Icon (включение и замена иконки) и Prefix (включение и текст). Кнопки Action — вложенные Icon Button со свойствами Size, Type, State, Loading, Icon, Focused.   
Inverse плагин собирает режимом dark на фрейме, а не отдельным вариантом (`docs/architecture.md`).   

## Что наследник может менять   
- Набор частей в Leading и Trailing Zone (например, у Password Input на месте Action-1 стоит Show / Hide);   
- Число строк Content (Text Area);   
- Клавиатурную модель — поэтому такой наследник и становится отдельным компонентом.   

Наследник не меняет порядок Trailing Zone, набор и смысл состояний, их приоритет и различие Disabled и Read Only.

# Masked Input   
*(добавлено docs-writer 19.09.2026)*

Masked Input — Input с маской формата: поле принимает только допустимые символы и само расставляет разделители. Вид и клавиатура те же, что у Input, поэтому это настройка Input, а не отдельный компонент.   

## Использовать   
- Формат фиксирован и одинаков для всех пользователей: телефон одной страны, дата, номер карты, код подтверждения;   
- Разделители помогают прочитать значение: `+7 999 123-45-67`, `12.03.2026`.   

## Не использовать   
|                                                  **Задача** |                                  **Решение** |
|:------------------------------------------------------------|:---------------------------------------------|
|               Формат зависит от страны или бывает разным |   Input без маски, нормализация и валидация |
|                             Имя, адрес, произвольный текст |                                        Input |
|                              Число с min / max или шагом |                                 Number Input |
|                                  Дата с выбором по календарю |                          Date Picker (позже) |

## Правила   
- Показывайте формат текстом в Description до ввода, а не только в Placeholder: Placeholder исчезает, как только пользователь начинает печатать;   
- Маска не заменяет валидацию: неполное значение — это Error с текстом, например «Введите номер полностью»;   
- Принимайте вставку в любом виде: `89991234567`, `+7 (999) 123-45-67` и `8 999 123 45 67` приводятся к одному значению. Пробелы, скобки и дефисы отбрасываются, а не вызывают ошибку (GOV.UK советует принимать значение в привычном пользователю виде);   
- Каретка не перескакивает при вводе и удалении; Backspace удаляет символ, а не разделитель;   
- Не блокируйте ввод молча: если символ не подходит, значение не меняется, а при повторных попытках появляется подсказка;   
- В форму отправляется нормализованное значение без разделителей, если сценарий не требует иного.   

## Доступность   
- Формат описывайте в Description и связывайте через `aria-describedby`;   
- Шаблон вида `__.__.____` внутри поля не заменяет Label и Description: screen reader читает подчёркивания как символы;   
- Используйте подходящие `inputmode` и `autocomplete` (раздел ниже).

# Типы значения (email, tel, url)   
*(добавлено docs-writer 19.09.2026)*

Тип значения меняет клавиатуру на телефоне, автозаполнение и встроенную проверку браузера. Вид Input при этом не меняется, поэтому тип — свойство Input, а не компонент.   

|                           **Значение** |                          **HTML** |                   **Автозаполнение** |                                                        **Особенности** |
|:---------------------------------------|:----------------------------------|:-------------------------------------|:-----------------------------------------------------------------------|
|                                  Email |                    `type="email"` |               `autocomplete="email"` |    Без автокоррекции и заглавной первой буквы; формат проверяется после ввода |
|                                Телефон |                      `type="tel"` |                 `autocomplete="tel"` |   Один формат — Masked Input; международные номера — без строгой маски |
|                                 Ссылка |                      `type="url"` |                 `autocomplete="url"` |          `https://` можно показать в Prefix, если протокол фиксирован |
| Числовой код: ИНН, код подтверждения, номер договора | `type="text"` + `inputmode="numeric"` | `autocomplete="one-time-code"` для кодов подтверждения | Это не число: ведущие нули важны, ↑ / ↓ значение не меняют. Не Number Input |

- Не используйте `type="number"` для кодов и идентификаторов: браузер отбросит ведущие нули и будет менять значение колесом мыши (так же советует GOV.UK);   
- Встроенные сообщения браузера о формате не заменяют Validation Message в Field: показывайте свой текст.

# Inline Input   
*(добавлено docs-writer 19.09.2026; вид к согласованию)*

Inline Input — вид Input без видимого контейнера в покое: значение выглядит как обычный текст, а контейнер появляется при Hover и Focused. Клавиатура и состав те же, что у Input, поэтому это настройка вида, а не отдельный компонент.   

## Использовать   
- Ячейка таблицы, заголовок карточки, строка настроек — где значение чаще читают, чем правят.   

## Не использовать   
|                                                                   **Задача** |                                  **Решение** |
|:-----------------------------------------------------------------------------|:---------------------------------------------|
|                                                  Обычное поле формы с Label |                               Input в Field |
|   Режимы «просмотр → редактирование» с кнопками Сохранить / Отменить |        Inline Edit (отдельный компонент, позже) |

## Правила   
- В покое значение должно читаться как редактируемое: при Hover появляется контейнер, курсор — текстовый;   
- Focused выглядит так же, как у Input: заметный индикатор фокуса обязателен (WCAG 2.2, критерии 2.4.7 и 2.4.11);   
- Доступное имя обязательно: видимого Label нет, поэтому используйте `aria-label` или `aria-labelledby` (например, заголовок колонки);   
- Error делает контейнер видимым; сообщение показывается рядом с полем и связывается через `aria-describedby`.

# Решения для согласования   
*(добавлено docs-writer 19.09.2026)*

1. **Focused поверх Error.** Макет убирает оформление валидации в Focused. Предлагаем: меняется только обводка, а текст ошибки в Field и `aria-invalid="true"` остаются, пока значение не проверено заново. Иначе пользователь, вернувшийся исправлять поле, теряет объяснение.   
2. **Tooltip на State Icon — дополнение, а не замена сообщения.** Текст ошибки всегда виден в Validation Message Field; Tooltip только повторяет его (`field.md`: критичные инструкции не прячутся только в Tooltip).   
3. **Enter в таблице «Управление клавиатурой».** В браузере Enter не переводит фокус на поле; в однострочном поле он отправляет форму. Предлагаем строку «Tab / Enter» читать как «Tab». Текст пользователя не изменён.   
4. **Состояние в Inverse-доске макета подписано «Pressed»,** в Regular — «Focused». Считаем это одним состоянием Focused (Pressed у Input нет, см. раздел «Состояния»).   
5. **Кликабельная область Clear 24 / 28 / 32 px** (по подписям макета) нужно сверить с уровнем 2: сейчас зона кнопки внутри поля на уровне 2 — 20 / 24 / 28. 20 px меньше минимума WCAG 2.5.8 (24 × 24).   
6. **Порядок приоритета состояний** (Disabled → Read Only → Focused → валидация → Hover) выведен из таблиц пользователя. В исходнике он не записан явно.   
7. **Chevron — последним в Trailing Zone** у контролов с Dropdown; нужно подтвердить с Select-семейством.   
8. **Inline Input — значение свойства вида у Input**, а не отдельный компонент. Inline Edit с режимами и кнопками Сохранить / Отменить — отдельный компонент позже.   
9. **Маска принимает вставку в любом виде и нормализует её.** Маска применяется только для одного фиксированного формата; для международных телефонов — без маски.
