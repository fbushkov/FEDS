# Checkbox&CheckboxCard

# Checkbox

**Checkbox** — интерактивный элемент множественного выбора. Он позволяет выбрать любое количество независимых вариантов, подтвердить условие или управлять выбором дочерних элементов.

> **Главное отличие от RadioButton**: Checkbox допускает выбор нескольких вариантов или отсутствие выбора. Если из группы можно выбрать только один вариант, используйте Radio.

> **Главное отличие от Toggle**: Checkbox обычно фиксирует выбор внутри формы и применяется после подтверждения. Toggle изменяет настройку сразу.

## **Использовать**

* Множественный выбор из списка независимых вариантов;
* Подтверждение условия: «Я принимаю правила»;
* Выбор элементов в таблице, списке или дереве;
* «Выбрать все» с состоянием Indeterminate.

## **Не использовать**

* Если разрешен выбор только одного варианта — используйте Radio;
* Если изменение применяется мгновенно, как настройка on/off — используйте Toggle;
* Если нужен компактный интерактивный фильтр или удаляемое значение — используйте Chip;
* Не смешивайте обычные Checkbox и Checkbox Card в одной группе: карточки будут выглядеть более приоритетными.

## Логическое состояние

Логическое состояние не следует смешивать с интерактивными состояниями Hover, Pressed или Focused.

| **Состояние** | **Описание** | **Когда применять** |
|----|----|----|
| Unchecked / No Active | Вариант не выбран | Базовое состояние |
| Checked / Active | Вариант выбран | Пользователь включил опцию |
| Indeterminate | Выбрана только часть дочерних элементов | «Выбрать все», группы и древовидные списки |

Indeterminate не означает ошибку или недоступность. Это промежуточное состояние родительского Checkbox:

* Ни один дочерний элемент не выбран → Unchecked;
* Все дочерние элементы выбраны → Checked;
* Выбрана только часть элементов → Indeterminate.

## **Размеры**

| **Размер** | **Где применять** |
|----|----|
| M | Стандартный размер: формы, таблицы, фильтры, плотные списки |
| L | Интерфейсы с более крупной типографикой, длинными подписями и увеличенной активной областью |

* Все Checkbox в одной группе должны быть одного размера;
* Не уменьшайте активную область до визуального квадрата Checkbox: в нее должна входить подпись;
* Для touch-интерфейсов используйте L или обеспечьте достаточные отступы вокруг M.

## Направление

| **Вариант** | **Описание** | **Когда применять** |
|----|----|----|
| Left | Checkbox расположен слева от контента | Стандартный вариант для форм, списков и фильтров |
| Right | Checkbox расположен справа от контента | Строки и списки, где элементы управления выровнены по правому краю |

## Конфигурация

| **Конфигурация** | **Состав** | **Применение** |
|----|----|----|
| Text | Checkbox + название | Базовый вариант |
| Description | Checkbox + название + пояснение | Когда нужно уточнить последствия или содержание выбора |
| Avatar | Checkbox + аватар + название, опционально описание | Выбор пользователя, исполнителя, команды или сущности |
| Без видимого текста | Только Checkbox | Только в плотных таблицах, когда контекст однозначно задан строкой или колонкой |

## **Название и описание**

* Название формулируйте как понятное утверждение или самостоятельный вариант;
* Используйте позитивные формулировки: «Получать уведомления», а не «Не отключать уведомления»;
* Подпись должна однозначно объяснять оба результата: что произойдет при Checked и при Unchecked;
* Description дополняет название, но не заменяет его;
* Не помещайте в Description критически важное условие, которое пользователь может пропустить.

## Перенос и сокращение текста

По умолчанию длинное название и Description переносятся на следующую строку.

В плотных интерфейсах допустимо сокращение:

* Название — одна строка с многоточием;
* Description — одна или несколько строк по правилам продукта;
* Полный текст показывается в Tooltip;
* Tooltip не должен быть единственным способом узнать обязательное условие.

## Состояния

| **Состояние** | **Когда применяется** | **Поведение** |
|----|----|----|
| Default | Компонент готов к взаимодействию | Может быть Unchecked, Checked или Indeterminate |
| Hover | Курсор находится над активной областью | Подсвечивается интерактивная область |
| Pressed | Момент нажатия | Отображается состояние нажатия |
| Focused | Навигация с клавиатуры | Видимый Focus Ring |
| Disabled | Выбор недоступен | Состояние нельзя изменить |
| Loading | Контент или значение еще загружается | Показывается Skeleton, взаимодействие недоступно |
| Error | Обязательное условие не выполнено | Ошибка обозначается визуально и текстом |

#### Активная область

Для обычного Checkbox активной является общая область **Checkbox + Text**. Если в конкретном интерфейсе требуется дополнительная фоновая подсветка Hover или Pressed, она задается в макете на уровне контейнера строки.

#### Disabled

* Сохраняйте видимым текущее логическое состояние;
* По возможности объясняйте причину недоступности рядом с компонентом.

#### Loading

* Используйте, если значение или подпись загружаются асинхронно.
* Не показывайте активный Checkbox до получения данных.

#### Error

Error применяется опционально, когда Checkbox или группа Checkbox обязательны для продолжения сценария.

* Не окрашивайте Checkbox в Error только потому, что он не выбран;
* Показывайте Error после валидации.

## **Композиция**

#### Группа Checkbox

* Размещайте варианты вертикально, если горизонтальная компоновка затрудняет связь подписи с Checkbox;
* Добавляйте общий заголовок-вопрос;
* Опции располагайте в логичном порядке: по частоте, этапу процесса или приоритету;
* Не смешивайте размеры, направления и визуальные варианты внутри группы;
* Для обязательной группы укажите условие заранее: «Выберите хотя бы один вариант».

#### Indeterminate — «выбрать все»

* Indeterminate показывает частичный выбор;
* Родительский Checkbox размещается перед дочерними элементами;
* Состояние родителя автоматически рассчитывается по дочерним значениям;
* Нажатие Indeterminate приводит группу к состоянию — выбрать все элементы;
* После изменения дочернего элемента состояние родителя обновляется сразу.

#### В таблице

* Checkbox в заголовке колонки управляет выбором всех доступных строк;
* Массовые действия появляются только после выбора хотя бы одной строки;
* Disabled-строки не должны учитываться как доступные для выбора.

## **Делать**

* Делайте кликабельными Checkbox и связанную с ним подпись;
* Используйте Checkbox для независимых вариантов;
* Используйте Indeterminate только для агрегированного выбора;
* Сохраняйте единые размер, направление и конфигурацию в группе;
* Для Checkbox Card делайте активным весь контейнер;
* Используйте перенос для длинного текста.

## **Не делать**

* Не используйте Checkbox для взаимоисключающих вариантов;
* Не формулируйте подписи через двойное отрицание;
* Не делайте кликабельным только маленький квадрат;
* Не размещайте вложенные интерактивные элементы внутри активной Checkbox Card;
* Не смешивайте обычные Checkbox и Checkbox Card в одной группе;
* Не используйте Indeterminate как самостоятельный вариант ответа.

## **Доступность (A11y)**

* Предпочтительно использовать нативный <input type="checkbox"> со связанным <label>;
* Checkbox должен получать фокус по Tab и переключаться клавишей Space;
* Клик по Label должен переключать Checkbox и увеличивать активную область;
* Для кастомной реализации используйте role="checkbox" и aria-checked="false", "true" или "mixed";
* Для группы связанных Checkbox используйте <fieldset> и <legend>;
* Description и сообщение об ошибке связывайте через aria-describedby;
* Required передавайте программно и поясняйте пользователю до отправки формы;
* Минимальная активная область — 24 × 24 CSS px; для touch-сценариев желательно стремиться к 44 × 44 CSS px;
* Checkbox Card должна быть одной интерактивной сущностью, а не отдельными focusable-карточкой и Checkbox.

## **Адаптив**

* На mobile увеличивайте активную область, не уменьшая ее до визуального Checkbox;
* Длинные подписи переносятся, Checkbox остается выровнен по первой строке;
* Checkbox Card на экране телефона занимает всю доступную ширину;
* Многоколоночная сетка карточек перестраивается в одну колонку;
* Не используйте горизонтальный скролл для обязательных вариантов формы;
* Сохраняйте видимый Focus для устройств с подключенной клавиатурой.

## **Связанные компоненты**

| **Компонент** | **Когда использовать вместо Checkbox** |
|----|----|
| Radio / Radio Card | Можно выбрать ровно один вариант |
| Toggle | Настройка применяется сразу после переключения |
| Chip | Компактный фильтр, тег или интерактивное выбранное значение |
| Select / Multiselect | Вариантов много или требуется поиск |


# CheckboxCard

Checkbox Card — расширенный вариант Checkbox с контейнером. Он используется, когда требуется сделать выбор заметнее, а для принятия решения пользователю недостаточно короткой подписи и нужно показать подробное описание и дополнительную информацию.

## **Использовать**

* Выбор Checkbox Card является главным действием на экране;
* Вариантам требуется пояснение, чтобы пользователь мог их сравнить;
* Нужно показать дополнительную иконку;
* Требуется крупная активная область для desktop и touch.

## **Не использовать**

* Для простого списка коротких названий — используйте обычный Checkbox;
* Для длинного списка — используйте Select или Multiselect;
* Не используйте карточки разных размеров или направлений в одной группе.

## Размеры

| **Размер** | **Где применять** |
|----|----|
| M | Стандартные карточки с коротким названием и опциональным Description |
| L | Карточки с аватаром, более длинным описанием или увеличенной активной областью |

## **Направление и иконка**

| **Вариант** | **Структура** | **Применение** |
|----|----|----|
| Left | Checkbox → контент | Стандартная карточка выбора |
| Right | Контент → Checkbox | Контент является первым объектом сканирования, контроль выровнен справа |
| Right + Icon | Иконка → контент → Checkbox | Только для варианта с Checkbox справа |

* Дополнительная иконка используется только при направлении Right;
* В одной группе сохраняйте одинаковое направление и одинаковую структуру карточек.

## **Конфигурация**

| **Конфигурация** | **Состав** | **Применение** |
|----|----|----|
| Text | Название | Минимальный вариант карточки |
| Description | Название + пояснение | Сравнение условий, характеристик или последствий выбора |
| Avatar | Аватар + название, опционально Description | Выбор пользователя, команды или связанной сущности |
| Icon | Иконка + название, опционально Description | Категории и варианты, которые легче различить визуально |

## **Состояния**

Checkbox Card наследует логические состояния Checkbox: Unchecked, Checked и Indeterminate.

| **Состояние** | **Активная область и отображение** |
|----|----|
| Default | Вся карточка доступна для выбора |
| Hover | Активна и подсвечивается область всего контейнера |
| Pressed | Состояние нажатия отображается на всем контейнере |
| Focused | Видимый Focus Ring у интерактивного Checkbox; карточка не создает дополнительную Tab-остановку |
| Disabled | Весь контейнер и его контент недоступны |
| Loading | Сохраняется контейнер карточки, внутри отображается Skeleton |
| Error | Ошибка обозначается у карточки и сопровождается текстовым сообщением |

#### Активная область

* Клик в любой точке контейнера должен переключать Checkbox;
* Внутри должна быть одна focusable-точка — сам Checkbox;
* Контейнер не должен получать отдельный `tabindex`;
* Курсор, Hover и Pressed должны подтверждать кликабельность всего контейнера.

#### Сетка

* На широком экране карточки можно размещать в несколько колонок;
* На узком экране перестраивайте их в одну колонку;
* Вся сетка использует один размер и направление.
